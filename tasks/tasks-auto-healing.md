## 2. 프로젝트 목표

**프로젝트 주목적과 최우선 목표는 Auto Healing이다.** 지원 가능한 공개·비상업 데이터로 선박 관측과 국가별 해상 수출입 카테고리를 조회하는 웹앱 ‘선박 해상 화물 모니터’를 적용 업무 서비스로 삼고, 수집 장애의 탐지→진단→제한 복구→독립 검증→차단/사람 인계를 구현·측정하는 것이 핵심이다. 지도·통계·별도 읽기 전용 조회 AI는 이 핵심을 적용할 업무이며 제품의 Monitor/Diagnosis/Recovery/Verification/Orchestrator/Notification 6역할을 유지한다.

핀란드 한정·고정 국가목록·100척 제품 상한은 두지 않는다. 활성 공급자의 실제 수신범위·사용 자격·약관·쿼터·확인된 자료가 실제 제공 범위를 정한다. 전 세계 완전 수신이나 무한 자원을 보장하지 않으며 계정/키/연결을 늘려 제한을 우회하지 않는다. 수신 해역·선박 기국·통계 보고국·상대국·현재 위치 국가는 별개이고 통계 국가 선택이나 지도 이동이 수집 범위·이력·예산을 임의로 변경하지 않는다.

통계는 ① 실제 Sea 운송모드가 확인된 국가별 수출입 상품(HS 2자리→4자리 한 단계 펼침 초기안), ② 기존 핀란드 12jd 월별 서비스 6분류/공식 16품목, ③ Eurostat 분기 화물형태 5개와 TOTAL을 구별한다. 상품·화물형태·AIS 선종을 임의 매핑하거나 국가 통계에서 개별 선박 실제 적재품목을 추정하지 않는다. 확인된 중량과 단위만 톤으로 변환한다. 월24개월+직전1개월·분기8분기+직전1분기 목표를 유지하며 연자료만 있으면 명시적 연간모드의 최근공개2년+직전1년 초기안을 적용한다.

관측 원본/판정/정책/항적 최소근거의 UTC 달력 rolling 2년과 운영 사건 종료 후30일을 구별한다. 2년 보존은 과거2년 즉시 확보가 아니다. 회색 미수신·마지막 유효 위치/경과 시간·실제 축적 항적·주황 공백 점선·붉은 이상 단절은 유지한다.

**목표가 아닌 것:** 공개/클라우드 배포·유료 의존·실제 선박/제공자 제어·정밀 경로 예측·근거 없는 품목 세분화/임의 재분류·임의 검색/복구 제어형 챗봇·추가 수신기 설치/데이터 기여 경로. AISHub와 AIS Friends는 현재 후보·연동 작업·후속 자동선택에서 명시 제외한다. 로컬 Windows11·최신 안정 Chrome/Edge·교육 실습 범위를 유지한다.

## 3. 작업 원칙과 Phase A — PRD 분석

### 현재 작성 판단과 역할 경계

**사용자 범위 변경을 반영한 조건부 상세안이다.** 상위 8개의 이름·순서를 유지하며 Phase C 분해, D 필수 작업 연결, E 추적, F 의존 순서, G 일정·위험을 계획한다. 기술·자료 미결정은 §11의 선행 게이트로 남긴다. 이것은 구현 준비 완료나 제품 성능/검수 통과 판정이 아니다. 현재는 세 문서만 개정하며 이 작성자는 작업목록만 수정하고 03을 실행하지 않는다. 정상기준선·복구 통제·필수 기록은 P0다. 모든 미지원 후보 연동이나 AI 미정 때문에 독립적으로 가능한 Healing 준비까지 막지 않되 초기 시연과 전체 제품 완료는 구분한다.

모든 하위 작업의 수행·검증·증거는 미래 계획이다. 기능 작성자는 실패 조건/검증 자료를 준비하고 최소 구현·수정만 한다. 실제 검증 실행·판정·근거 보고는 별도의 검수자에게 맡긴다. 각 작업의 개별 검증 → 2.5/3.8/4.6/5.6/6.8/7.5의 모듈 접점 검증 → 상위8의 전체 실습으로 범위를 구별하며 동일 검증을 무조건 세 번 반복하지 않는다. 순수 검증 작업의 대상 파일은 읽고 실행할 대상이지 검수자가 수정할 파일이 아니다. 실패 수정은 작성자가 담당한다.

후속 실행에서도 문서/코드 작성과 검수를 한 에이전트에 겸임시키지 않는다. 여러 검수 에이전트는 병렬로 실행하지 않고 선행 통과·원문/버전/해시·판정 근거 체크포인트를 보존한 뒤 다음 단계로 이동한다. 실패하면 직전 유효 선행 체크포인트에서 필요한 부분만 수정하고 영향받는 가장 이른 검수부터 다시 순차 진행한다. 이번 문서의 검수 배정과 보존 방식은 §12에 적는다.

**예상 대상 파일 규칙:** §5의 docs/설계·src/코드·tests/검증·artifacts/증거 경로와 README는 모두 미래 산출물의 논리적 가안이며 이번에 생성하지 않는다. 확장자 .*는 기술 미선정 상태의 자리표시다. 1.2/1.5(AI는 1.3/7.1)에서 실제 경로·확장자·실행 방법을 정하고 추적표를 갱신한다. 제시 경로가 현재 존재하거나 코드 스택이 정해졌다는 뜻이 아니다. 완료 증거의 기본 보관 위치도 artifacts/verification/<작업ID>/ 가안이며 검수 보고의 경로/형식은 후속 단계에서 확정한다.

상위 번호는 승인된 범위/순서이며 모든 하위의 일괄 직렬 실행 순서는 아니다. P0는 공통 의존/안전 통제, P1은 승인 사용자 기능의 배치 우선순위다. P1도 필수이며 생략 승인이 아니다. 제품의 Monitor/Diagnosis/Recovery/Verification/Orchestrator/Notification 6역할과 별도 읽기 조회 AI의 책임은 유지하며 이를 모두 별도 LLM으로 만들지는 않는다.

### A.4 미결정·위험 요소의 처리

§10은 일정/자료/모델 위험, §11은 OPEN-01~12의 연결 작업·결정 게이트를 기록한다. OPEN-07은 이전 PRD v0.2.1 승인 해소 이력이다. 현재 명시 범위 변경과 새 세부안 전체 승인은 구별하며 OPEN-11·12와 기존 기술/자료 미정은 유지한다. 게이트 확인 실패 시 영향을 받는 구현 진입/완료 선언을 보류하며 독립적인 작업까지 불필요하게 차단하지 않는다.

[자료 가용성](https://uncomtrade.org/docs/data-availability/), [운송모드](https://uncomtrade.org/docs/mode-of-transport-and-trade-routes/), [HS 상하위 포함관계](https://uncomtrade.org/docs/are-6-digit-commodity-codes-included-in-4-digit-commodity-codes-or-are-they-separate/)를 확인 대상으로 삼는다. ## 6. 요구사항 추적표 — Phase E

FR 18개·NFR 10개의 정방향 연결은 아래 표, 역방향 연결은 §5의 각 작업 “관련 요구사항”이다. 작업과 요구의 연결은 **설계/기술 게이트 → 정상/격리 기반 → 구현·적용 → 개별/모듈 검증 → 전체 통합/실험 → 취합/보고** 역할로 구별한다. 범위 표기 FR-001~003·005~019는 폐기 ID를 제외한18개이며 NFR-001~010은10개 전체다.

“구현·적용” 열의 각 작업은 해당 §5 테스트·검증 필드의 **별도 검수자 개별 검증**까지 연결한다. 검증 열에서 “개별:” 뒤에 이를 명시하고 “모듈:” 뒤에 접점 검증 작업을 표시한다. 설계/기술 게이트 및 정상/격리 기반 작업의 자체 필수 검증 계획은 해당 §5 필드를 따르며 본 기능 구현으로 승격하지 않는다. 모든 작업은 pending이고 아래 연결은 실행/통과 결과가 아니다.

- 1.1~1.5와1.7은 요구의 계약/선택/예산을 준비하는 선행 책임이며 기능 구현 완료를 뜻하지 않는다.

#### 원문·버전·해시 체크포인트와 실패 복구

- 작성 전 `detail_tasks_before_tasks`, `detail_tasks_before_prd`, `detail_tasks_before_worksheet`에 실제 전체 원문·경로·SHA-256·버전을 도구 저장소로 보존했다. 입력 해시는 §1에 있다. 기존 파일의 원문을 확인한 뒤 승인 상위의 상세화만 갱신한다.
