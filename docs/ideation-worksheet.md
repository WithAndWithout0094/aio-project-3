# 1. 서비스 선정

## 1.1 어떤 서비스의 장애를 자동 복구할 것인가?

**확정한 서비스 범위:** 제품명은 선박 해상 화물 모니터다. 핀란드·100척 제품 상한을 없애며 지원 가능한 공개·비상업 자료의 실제 확보 범위에서 선박 관측·실항적과 국가별 해상 수출입 카테고리를 제공한다. 부채꼴은 제거하고 기존 카드·2년 보존·공백/이상·읽기 조회 AI를 유지한다.

새 행동·소식 기능은 P1 필수 지원 기능이다. 초기 NAV/NEWS 계약은 제안이며 상세 행동 기준 OPEN-13, 공급자·권리·쿼터·조회/재조회·보존 계약 OPEN-14는 활성 전 확인한다. 신규 기능이 Auto Healing P0의 독립 준비를 막지 않게 한다.

**한 문장 설명:** Auto Healing이 프로젝트의 주목적이며 수집 장애의 탐지→진단→제한 복구→독립 검증→차단/사람 인계를 핵심으로 하고 지도·통계·조회 AI는 이를 적용·검증하는 업무 서비스다.

**주요 사용자:** 일반 사용자, 기업, 개인사업자의 선박·물류 현황 확인 담당자.

**정상 실행 흐름**

- 선박: 사용자 → 웹 지도·선박 선택 → 수집 서비스 → 자격/범위가 확인된 활성 AIS 공급자 → 관측 위치·시각·항적·상태·팝업.
- 화물: 사용자 → 국가 사이드 선택 → 가용 자료 모드·방향·기간·분류 → 공식 해상 통계 → Sea 수출입 상품(월/연)·핀란드 월품목·분기 화물형태의 구별·중량/비중/변화·근거 표.
- 항적: 선박 상세 카드 → 항적 보기 → 기간 선택 → 실제 확보 관측·주황 공백 점선/붉은 이상 단절·구간 표.
- 소식: 유효 항적/비교 근거 → 행동 후보·원인 불명 → 허용 공급자 제한 수집·정규화 → 관련성/출처 → 카드·항적 소식 및 저장 자료 읽기.
- 질문: 자연어/화면 조건 → 제한 조회 조건·가용성 확인 → 허용 읽기·결정적 계산 → 근거 응답 또는 명확화/정형 대체.
- 자동 복구: 수집 장애 관찰 → 근거에 따른 진단 → 허용된 복구 → 독립 검증 → 정상 확인 또는 중단·사람에게 전달.

## 1.2 서비스가 멈추면 어떤 영향이 발생하는가?

**사용자 영향:** 오래된 위치를 현재 위치로 오인하거나 선박·품목 현황을 확인하지 못한다. 관측 연결선이 실제 이동경로처럼 보이거나 누락된 통계가 0으로 표시되면 잘못된 해석을 할 수 있다.

**운영 영향:** 제공 서비스와 자체 수집기 중 어느 쪽의 문제인지 확인하고, 재시도·재기동 후 정상 여부를 다시 확인해야 한다.

**데이터·비용·보안 영향:** 재처리로 이력이 중복될 수 있고 잘못된 좌표·통계로 정상 자료를 덮어쓸 위험이 있다. 원본과 마지막 정상 자료를 보존해야 한다. 실제 개인정보·결제·운영 DB를 실습에 사용하지 않으며 클라우드 외 유료 서비스는 제외한다. 초기안은 로컬 실습이며 클라우드 사용·외부 공개는 MVP 밖이다. 향후 전환 시 예산·접근 조건을 새로 정한다.

**심각도:** 중간 — 일부 요청 실패·정보 지연과 운영 대응이 필요한 서비스라는 선정안 기준. 항해 안전을 보장하거나 선박을 직접 제어하는 서비스 범위는 포함하지 않는다.

### 지도·동적 감시와 관측 공백

활성 수집 범위에서 유효 신규 선박이 발견되면 감시 집합에 추가한다. 단순 미수신·필터 변경으로 기존 선박을 교체하거나 삭제하지 않는다. 집합 버전·변경 시각·이유를 영속 보존하고 명시적 범위 변경에 따른 비활성화에도 항적·열린 사건은 보존한다. 지도와 목록은 같은 조건·기준 시각·집합 버전을 사용하며 전체 일치 수와 페이지/영역별 표시 수를 구별한다. 페이지·지도 영역·표시 축약은 응답/렌더링 장치이며 저장 선박 수 상한을 대신하지 않는다.

공급자별 원본은 보존한다. 같은 MMSI의 동일 관측을 여러 공급자가 전달해도 최신성·평균·관측 횟수를 부풀리지 않는다. 대표 위치는 최신 유효 전체 레코드에서 선택하며 서로 다른 출처·시각의 위치/SOG/COG를 합성하지 않는다. 동시각 위치 충돌은 보존·표시하고 임의 정상화하지 않는다. 과거·미래·단위 오류 자료는 최신 유효 위치를 덮어쓰지 않는다.

제품의 REST 정규 조회는 5분, 스트림은 공급자 방식의 지속 수신이며 제품 상태 점검 주기와 구별한다. 정상 WebSocket 연결 수명에 10초 요청 제한을 적용하지 않는다. 개별 메시지 부재만으로 연결·프로세스 장애를 판정하지 않고 공급자별 건강 신호 계약을 확인한다. Digitraffic의 시각 단위·흘수·미제공 값 해석을 다른 공급자에 일괄 적용하지 않는다.

| 상태·행동 | 요구되는 화면 결과 |
|---|---|
| 정상 관측 | 유효 좌표의 방향 화살표, 방향이 없으면 방향 없는 표식·부족 표시 |
| 위치 도약 의심 | 원본 별도 보존/표시, 유효 항적·평균의 기준으로 자동 채택하지 않음 |
| 신규 원본 공백 | GAP-01의15분 기준 회색·마지막 유효 위치·경과 시간 |
| 회색 선박 선택 | 상세 카드와 공백 상태·실제 축적 항적 접근 |
| 유효 재관측 | 새 유효 위치·정상 색으로 복귀, 공백 이력 보존 |

5분은 조회/점검 주기이며 모든 선박의5분 이내 신규 관측을 보장하지 않는다. 중복 재조회로 관측 시각을 갱신하지 않는다.

### 선박 상세 카드와 기국 필터

선박 클릭 카드에는 이름·MMSI·IMO, 확인된 기국, 원천 선종, 마지막 위치·신선도, SOG/COG, AVG-01~02의 최근 관측 속도 평균(구간·표본 수), 흘수, 목적지 원문, 항만/시간, 원천 항해 상태와 품질·공백 상태를 제공한다. 현재 위치 국가·출발/도착 국가·실제 적재 화물은 각각 별도 근거가 있을 때만 표시한다. 국가 통계나 선종을 실제 적재 화물로 바꾸지 않는다.

항만 방문·항해 연결에는 출처·방문 식별자·항만·시각 종류를 보존한다. **ATD=실제 출항, ATA=실제 입항, ETA=예상 입항, ETD=예상 출항**을 구별하고 정확히 같은 항해의 출발/도착 방문임을 확인한 경우에만 “출발 → 도착”으로 연결한다. 이전/다음 항구를 최초 출발/최종 도착으로 승격하지 않는다. AIS reported ETA는 연도 없는 MMDDHHMM UTC 값이라는 한계를 표시하고 임의 연도를 붙여 지연을 계산하지 않는다. 완전한 시각을 가진 항만 방문 ETA와도 구별한다.

Digitraffic의 이름·MMSI·IMO·shipType, 위치 sog/cog/navStat/timestampExternal 및 조건부 항만 방문 자료를 후보로 삼는다. shipType은 cargo 70/tanker 80처럼 축약될 수 있어 Bulk Carrier 등 상세 선종을 보장하지 않는다. draught는 0.1m 단위로 변환하고 0은 미제공으로 처리한다. 항목별 원천 갱신 시각·수집 시각과 부족 사유(미제공/연결 불가/자료 오래됨 등)를 구분한다. 사진은 재사용 권한이 확인된 경우에만 제공하고 기본은 자리표시자다. 사용자 첨부 3장은 UI 참고이며 복제·재사용 권한이 아니다.

기국 필터는 활성 공급자에서 실제 확보한 감시 집합 안에만 적용한다. 분석 대상 국가 사이드와 통계 상대국 선택과는 별개다. 해역 근거가 없으면 마지막 관측 위치를 현재 국가로 확정하지 않는다.

### 항적 조회와 공백 표현

선박 카드의 **항적 보기**에서 기본 24시간, 7일·30일·1년·2년·사용자 지정 기간을 선택한다(기간 프리셋과 기본값은 위임 초기안). 요청 기간과 실제 확보 기간을 함께 표시하고, 보존 전/수집 전·자료 없는 기간을 정상 항적으로 채우지 않는다. 지도에는 관측점과 관측 연결선을 구별하며 연결선은 두 관측 사이 실제 이동경로의 증명이 아니다.

신규 원본 관측 간격이 15분 이상인 공백은 재수신 후 양쪽 유효 위치가 있을 때 **주황색 점선**과 “미관측 구간 연결 — 실제 경로 아님”으로 표시한다. 재수신 전에는 마지막 유효 점과 열린 시간 구간만 표시하고 가짜 종점·추정 항적을 만들지 않는다. 위치 도약·동시각 충돌·시각 오류는 **붉은 이상 표식과 항적 단절**이며 공백 점선으로 변환하지 않는다. POS-03 추적 재개 때 이전 위치와 선을 잇지 않는다. POS-02의 30분 초과 도약 판정 유보와 15분 공백 시각화는 별개다. 이상이 끼어 있는 구간은 시간 공백이 겹쳐도 붉은 단절을 유지한다. 미수신 선박의 회색·마지막 유효 위치·경과 시간은 유지한다.

색·선형·범례·상태 문구와 구간 표(시작/끝·열림 여부·유형·근거)를 함께 제공한다. 장기 조회 축약은 조회 응답과 렌더링에만 적용한다. 원본을 삭제·덮어쓰지 않고 공백/이상 경계를 넘어 축약하지 않으며 각 구간의 양끝점을 보존한다. 원본 수·표시 수·축약 여부를 밝히고 과대 조회에는 구간별 페이지 또는 기간 축소 안내를 제공한다.

### 관측 누적 보존

관측 원본·품질 판정·해당 정책 버전·항적 단절의 시간/유형/최소 근거 참조는 **UTC 달력상 rolling 2년** 보존한다. 조회 기준 시각에서 연도를 2년 뺀 경계 시각을 포함한다(윤일이 대상 연도에 없으면 2월 말일의 같은 시각). 정상 시각의 원본은 observed_at, 시각 오류·전체 시각 미제공 격리 원본은 최초 first_received_at로 기한을 계산한다. 재조회로 최초 수집 시각이나 보존 기한을 연장하지 않으며 격리 원본은 정상 항적에 넣지 않는다. 조회에는 만료 경계를 즉시 적용하고 물리 만료 정리는 하루 1회 앱 전용 저장 범위에서 수행한다.

운영 복구 사건·시도·독립 검증 로그는 사건 종료 후 30일 보존한다. 열린 사건의 필수 근거는 종료 전 삭제하지 않아 일부 원본이 2년을 넘을 수 있지만 이는 일반 항적 조회 범위를 늘리지 않는다. 종료 후 각 기록의 기한을 적용한다. 사건 상세가 먼저 만료돼도 2년 항적에 필요한 단절 시간·유형·정책·최소 근거는 별도로 남기고 “운영 사건 상세 보존 만료”로 표시하며 삭제된 상세의 깨진 링크를 제공하지 않는다. 월 통계는 표시 24개월+직전 비교 1개월, 분기 통계는 표시8분기+직전 비교1분기, 연자료만 있으면 연2년+직전 비교1년 초기안으로 명시하며 비교 자료가 없으면 비교 불가다. 보유 통계의 원천·수정 버전과 누락 상태도 함께 보존한다. 대화 원문은 기본적으로 세션 안에서만 보관하고 2년 관측 정책을 적용하지 않는다.

2년 보존은 수집 시작 전 과거 2년의 즉시 확보를 약속하지 않는다. 공개 AIS 최신값과 서비스의 실제 축적 범위를 구분하고 시작·종료 시각과 미확보 기간을 표시한다. 과거 고정 100척 범위의 100×288×730=21,024,000건은 역사적 단순 예시일 뿐 현재 규모 계획이나 저장 상한이 아니다. 현재 추정은 공급자별 실제 신규 관측률×보존 기간에 원본·판정·색인·출처 비용을 더하며 스트림 원본과 5분 스냅샷을 구별한다. 730/731일의 달력 차이도 반영한다. 페이지·영역·큐·저장·과부하·취소의 수치와 장기 성능 예산은 OPEN-09 및 작업 1.4의 미확인 게이트다. 과부하를 이유로 조용히 100척만 저장하거나 2년 보존을 줄이지 않는다.

행동 판정과 최소 항적 근거는 기존 관측 UTC 2년 정책에 연결한다. 뉴스 메타데이터·매칭·변경 이력·조회 로그의 보존 기간은 OPEN-14에서 활성 전에 확정하며 관측 2년이나 운영 복구 종료 후 30일을 자동 적용하지 않는다. 권리·기간에 따른 만료는 화면과 조회 근거에 표시하고 깨진 근거 링크·만료/철회 자료의 AI 재인용을 막는다. 운영 복구 로그의 기존 30일과 열린 사건 예외는 유지한다. 세부 DB 타입·키·nullable·참조/만료 처리는 작업 1.8에서 구체화한다.

### 핀란드 해상 화물 화면

공식 12jd 표에서 확인한 16개 품목군을 다음의 서비스용 상위 분류로 묶는다. 사용자가 이 범위를 포함한 서비스를 승인했으므로 이 분류를 초안 기준으로 기록하며, 명칭 수정은 가능하다.

| 큰 분류 | 공식 하위 품목군 |
|---|---|
| 목재·제지 | 원목, 제재목, 펄프, 종이, 합판·단판 |
| 연료 | 원유, 석유제품, 석탄·코크스 |
| 금속·광물 | 광석·정광, 금속·금속제품, 원료광물·시멘트 |
| 화학·비료 | 화학제품, 비료 |
| 곡물 | 곡물 |
| 일반·기타 화물 | 일반화물, 기타 상품 |

- 이 절의 6/16 분류는 핀란드 월별 품목 모드에만 적용한다. 국가 사이드 선택과 가용 분기 모드는 다음 절을 따른다.
- 들어오는 화물/나가는 화물과 공개된 월을 선택한다. 상대국 선택을 늘리지 않는 최초 범위로, 상대국 전체 합계 기준을 사용한다.
- 큰 분류를 클릭하면 하위 품목군 목록만 한 단계 펼친다. 품목 선택 시 월별 톤수 라인 그래프를 보여준다.
- 상위 합계는 서로 중복되지 않는 하위 공식 품목의 합계다. 전체 합계 행을 개별 품목처럼 더하지 않는다.
- 전체 비중은 같은 월·방향·자료 범위의 전체 톤수를 분모로 한다. 상위 분류 내 비중을 추가하면 별도 이름으로 분모를 밝힌다.
- 전월 대비 변화량은 톤수 차이, 변화율은 전월 대비 비율이다. 비교 기간·집계 기준이 같아야 한다.
- 분모가 0이거나 비교 자료가 없으면 계산 불가. 미발표·비공개·누락은 실제 0과 구분하고 그래프에서 임의 보간하지 않는다.
- 금액·개수·TEU를 톤수와 혼합하지 않는다. 확인한 표에는 금액이 없으므로 금액 그래프를 약속하지 않는다.
- 월별 통계이며 관측 시점의 실시간 화물 적재 목록이 아니다. 통계 기준월·출처·갱신일과 확인 가능한 잠정치 상태를 표시한다.
- 통과물량 처리 범위는 원자료 정의 확인 대상이다. 핀란드 소비재·핀란드산 생산품으로 단정하거나 확인 없이 통과물량을 빼지 않는다.
- 생활용품·세제·식기 세부 분류는 12jd에 없다. 일반화물을 생활용품으로 개명하지 않으며 별도 HS 모드의 실제 확인 상품은 제공할 수 있다.
- 자료 수정 공표가 있으면 동일 기간 값도 변경될 수 있다. 원자료 버전/갱신 이력을 남길 요구가 있다.

### 국가 사이드와 세 통계 모드

분석 대상 국가 선택에는 고정 국가 상한을 두지 않으며 실제 지원은 원천·조합별 확인 결과로 표시한다. 보고국·상대국·선박 기국·수신 해역은 서로 다르다. 기존 Eurostat 조사 25개 보고국은 BE 벨기에, BG 불가리아, DK 덴마크, DE 독일, EE 에스토니아, IE 아일랜드, EL 그리스, ES 스페인, FR 프랑스, HR 크로아티아, IT 이탈리아, CY 키프로스, LV 라트비아, LT 리투아니아, MT 몰타, NL 네덜란드, PL 폴란드, PT 포르투갈, RO 루마니아, SI 슬로베니아, FI 핀란드, SE 스웨덴, NO 노르웨이, ME 몬테네그로, TR 튀르키예다. 이는 과거 확인 범위이며 제품의 국가 목록 제한이 아니다. EL 등 원천 코드는 보존한다.

- **국가별 해상 수출입 상품 모드:** UN Comtrade 등 후보에서 실제 Sea가 확인된 국가×기간×품목 조합만 제공한다. 위임 초기안은 HS 2자리→HS 4자리 한 단계 펼침이며 HS 6자리 추가 드릴다운은 포함하지 않는다. 분류체계·개정판·코드·레벨·부모를 보존한다. 기본 상대국은 전체 합계 초기안이며 복잡한 양자 무역 UI를 추가하지 않는다.
- **핀란드 월별 품목 모드:** Statistics Finland 12jd, 서비스 6분류·공식 16품목, Import/Export, 톤, 최신 공개 24개월+직전 비교 1개월. Country 차원은 상대국이므로 분석 핀란드에는 Country=Total을 사용한다.
- **분기 화물형태 모드:** Eurostat mar_go_qmc, THS_T(천 톤), TOTAL 및 가용 LBK 액체 벌크·DBK 건조 벌크·LCNT 대형 컨테이너·RO_TOT 로로·OTH 기타. IN/OUT은 하역/적재이며 수입/수출 상품으로 개명하지 않는다. 최신 공개 8개 달력 분기+직전 비교 1분기 확보 목표다. 연간 NST 20품목은 이번 범위에 추가하지 않는다.

HS·12jd 6/16품목·Eurostat 화물형태 사이 임의 매핑은 금지한다. 확인된 원천 상품 코드는 제공할 수 있으나 일반화물을 생활용품으로 바꾸는 근거 없는 세분화는 하지 않는다. AIS shipType cargo 70은 선종이며 적재 상품 품목이 아니다. 국가 통계를 개별 선박 적재 명세로 연결하지 않는다.

월 자료는 24+1개월, 분기 자료는 8+1분기이며 연자료만 확인되면 명시적인 연간 모드로 제공한다(초기안: 최근 공개 2년+직전 비교 1년). 연간값을 월값으로 생성하지 않는다. 중량 중심으로 확인된 중량 필드·단위만 톤으로 변환하고 원값·원단위·변환 근거를 보존한다. 금액·수량으로 중량을 대신하거나 금액·TEU 분석을 신규 필수 기능으로 넣지 않는다. 천 톤은 ×1,000, kg이면 ÷1,000이며 필드 단위가 확인된 경우에만 변환한다.

국가×원천×운송모드×분류판/레벨×주기×방향×분류×기간×상대국 범위의 가용성을 판정한다. **미지원, 미발표, 해당 기간 자료 없음, 비공개/결측, 일시 조회 실패**를 0과 구별하며 자격·Sea 확인 전은 별도의 **미확인**이다. 국가 변경 시 선택 식별자로 늦은 이전 응답을 격리한다. 이전 자료를 남기면 이전 국가 이름과 새 요청 상태를 함께 표시한다. 호환되지 않는 방향·분류는 해당 조합의 가용 전체값·최신 공개 기간으로 바꾼 이유를 알리고, 없으면 선택 해제·자료 부족을 표시한다.

국가 간 비교는 같은 원천·정의·운송모드·분류판·주기·단위·방향·상대국 범위·공통 기간만 사용한다. 서로 다른 분류판을 자동 비교하지 않는다. 비중 분모는 같은 조건의 원천 전체값이며 현재 페이지 품목 합계를 전체 분모로 쓰지 않는다. 상위 합계와 하위를 중복 합산하지 않고 필수 하위가 누락/비공개면 합계 불완전을 표시한다. TOTAL=IN+OUT을 가정하지 않는다. 직전 기간은 달력상 직전 월/분기/연도이며 결측을 건너뛰어 비교하지 않는다. 월·분기·연도를 이어붙이거나 누락을 보간하지 않는다. Eurostat의 분기 공표 지연(최대 10개월)과 국가별 포함 항만 차이도 알린다.

**Sea 확인 게이트:** 선행 조사에서 익명 Comtrade preview에 motCode=2100을 요청했지만 HTTP 200 응답 행의 motCode=0(전체 운송수단)이 확인됐다. 그러므로 요청 매개변수나 HTTP 성공만으로 해상 필터 성공을 주장하지 않는다. 정확한 실서비스 API·접근 자격에서 실제 Sea 행·상품 레벨·중량 단위를 확인해야 한다. Sea가 없으면 WATER/All Modes/미지정으로 대체하지 않고 미확인 또는 미지원으로 남긴다. 미지원 응답 처리를 구현하는 것과 해외 Sea 상품 확보는 별개이며 자료 미확보를 지원 완료로 표시하지 않는다.

### 항행 특이점과 관련 소식 — P1 지원 기능

사용자 요청은 평소 항로에서 벗어나거나 반복 선회하는 선박의 특이점을 최초 **원인 불명**으로 표시하고, 이후 관련 선박·해역의 뉴스와 공지를 출처와 함께 빠르게 갱신하는 것이다. Auto Healing P0의 수집 장애 처리와 분리된 P1 필수 업무 지원 기능이며, 새 보도만으로 원인을 확정하거나 위법·사고·의도를 추정하지 않는다.

흐름은 **유효 항적·비교 근거 확인 → 행동 특이점 후보/판정 불가 → 원인 불명 표시 → 구조화된 제한 조건 → 허용 공급자의 수집·정규화 → 관련성 연결 → 선박 카드·항적의 관련 소식 → 보유 자료 읽기 AI**다. 기존 선박 모니터링 화면의 카드·항적에 후보 구간, 판정 근거/부족 사유, 소식 목록을 붙인다. 별도 자유 웹검색 창이나 복구 버튼을 추가하지 않는다. 최초 로딩·미조회·원천 미활성·부분 실패·자료 없음·이전 자료와 갱신 실패를 문구로 구별하고 키보드 접근·색 외 표시·기존 초점 복원 규칙을 적용한다.

기사·제목·매체명·URL 등 외부 문자열은 비신뢰 데이터다. 기사 안의 지시로 읽기 AI·수집·복구의 권한이나 정책을 바꾸지 않는다. 조회 AI는 저장된 행동 후보·소식·연결 근거를 읽는 별도 허용 도구만 사용하며 임의 SQL·쉘·파일·URL 탐색/웹검색 금지는 유지한다. 기사 원문 접근 권한과 출처 메타데이터 표시 권한은 별도로 확인한다.

뉴스 수집기가 활성화된 뒤 실제 요청 오류·생존 장애가 확인될 때만 기존 허용목록·복구 상한을 적용한다. 기사 0건·새 기사 없음·429·자격 문제·항행 원인 불명을 무조건 재시작 사유로 삼지 않는다. 뉴스 정상화는 같은 공급자의 새 요청에서 계약상 유효 응답·저장·조회 상태를 독립 확인하며 빈 정상 결과도 허용한다. 새 기사 출현은 복구 성공의 필수 조건이 아니다. 추가 요청 3회·대기 5/15/30초·재시작 1회·활성 180초·300초 냉각/읽기 1회·운영자 확인 및 새 독립 검증·영속 한도는 확대하지 않는다. 뉴스 미준비는 기존 원천의 정상 기준선/초기 Healing을 막지 않으며 전체 제품 완료에서는 P1도 검증해야 한다.

# 2. 에이전트 설계

### 공급자별 사건과 독립 정상화 계약

Monitor·Diagnosis·Recovery·Verification·Orchestrator·Notification의 6역할은 provider/수집 스트림·설정 범위를 사건·요청·연결·검증 근거에 보존한다. 공급자 A 장애는 A의 사건 기준 이후 새 유효 관측으로 독립 확인하며, 공급자 B에서 같은 선박의 새 관측을 받았다는 이유로 A 사건을 종료하지 않는다. AIS 정상화의 관측 나이 0~10분·독립 검증 30초·활성 180초 조건을 유지하고 근거가 없으면 판단 불가로 남긴다.

계정 단위 쿼터·429 대기 지시를 준수하며 사건·영역·키·연결을 나눠 예산을 증폭하지 않는다. 독립 검증용 추가 연결도 같은 공급자 상한을 따른다. 인증·자격·권한 철회·쿼터 제한은 무조건 재시작하는 사유가 아니며 대기/중단/인계한다. 공급자 대기가 활성 기한을 넘으면 안전 중단한다. 개별 미수신·커버리지 부재·제공자 제외 선박·미공표·모델 실패도 수집 고장으로 승격하지 않는다.

통계 정상화는 같은 원천·보고국·상대국 범위·운송모드·분류판·주기/기간·방향·단위의 이미 공개된 자료로 독립 확인한다. HTTP 200만으로 해상 필터나 자료 정상화를 인정하지 않는다. 추가 요청 최대 3회(5·15·30초 대기), 허용 수집기 재시작 1회, 180초 기한, 차단 후 300초 냉각과 읽기 1회, 운영자 확인+새 독립 검증, 영속 한도와 금지 행동은 그대로 유지한다. 재생/실시간, 자동 정상화/안전 중단/사람 개입 결과를 분리한다.

활성 수집원별 정상 기준선을 확보하면 독립적으로 가능한 Auto Healing 준비를 진행할 수 있으며 미지원 후보 전체 연동이나 조회 AI·뉴스 준비 완료를 선행시키지 않는다. 초기 Healing 시연은 전체 제품 완료와 다르며 미확보 상품·후보 연동·미완료 필수 기능을 완료로 세지 않는다.

Auto Healing 대상 업무 에이전트는 6번 신호 공백·이상 탐지를 유지한다. Monitor/Diagnosis/Recovery/Verification은 자동 복구의 책임 경계이며 결정적 규칙으로 구현할 수 있다. 새 사용자 조회 AI는 별도 읽기 기능으로 제품 범위에 포함하며 무료/로컬 모델 후보와 실제 실행은 미검증이다. 특정 유료 모델·외부 전송을 임의 승인하지 않는다.

## 2.1 장애를 탐지하는 주체는 누구인가?

**이름:** Monitor 역할.

**관찰:** 수집 응답 상태·지연, 마지막 수집 성공, 수집기 생존 상태, 선박별 실제 관측 시각, 누적 유효 좌표, 통계의 공표 기간·조회 상태.

**판정:** 알려진 통신 오류와 수집 중단을 사건으로 기록한다. 선박별 공백·위치 이상은 별도 사건으로 구분한다. 임계값은 DEC-02/GAP·POS 정책에 정의하며 월별 통계 미발표는 장애가 아니다.

**출력:** 사건 식별자, 대상 서비스·선박, 관찰 시각, 증거, 사건 유형 후보. 설정 변경·재시작 권한은 없다.

## 2.2 원인을 진단하는 주체는 누구인가?

**이름:** Diagnosis 역할. 입력은 사건·수집 상태·원천 응답·관측 이력이다.

| 유형 | 의미 | 판단 근거 | 신뢰도·규칙 |
|---|---|---|---|
| 제공 요청 오류 | 5xx·응답 시간 초과 | 상태 코드·응답 대기·수집 로그 | 단독 신호로 제공자 전체 장애를 확정하지 않음 |
| 자체 수집 중단 | 수집기가 실행/응답하지 않음 | 별도 감시 주체의 생존 상태 확인 | 10초 간격 상태 점검 3회 연속 실패 |
| 선박 관측 공백 | 특정 선박의 새 관측만 없음 | 전체 수집 상태와 선박별 시각 비교 | 실제 신호 미송신·수신망 공백의 원인 확정 불가 |
| 위치 이상 의심 | 비정상적 좌표 변화 | 연속 유효 관측·시간 차·데이터 유효성 | POS-01~04의 판정·추적 재개 기준 |
| 통계 신규 공표 없음 | 다음 월 자료가 아직 없음 | 공식 공표 주기·기준월 | 정상 대기, 복구 사건으로 만들지 않음 |
| 수집 장애 원인 불명(UNKNOWN) | 증거 부족·충돌 | 근거와 불확실성 | 자동 변경 중단, 사람에게 전달 |

출력은 원인 후보·근거·허용 가능한 복구 방향·사람 필요 여부다. 직접 복구 실행은 금지한다. 항행 후보의 원인 불명은 이 수집 장애 UNKNOWN과 별개이며 기사·자료 없음만으로 복구를 유발하지 않는다.

## 2.3 복구를 실행하는 주체는 누구인가?

**이름:** Recovery 역할.

**허용 후보:** 한도가 있는 재조회·재연결, 격리된 환경의 허용목록 수집 프로세스 재시작. 횟수·대기는 DEC-05/POL-04~07, 대상은 사전에 등록된 자체 수집기로 제한한다.

**금지:** 임의 생성 명령 실행, 실제 선박·외부 API 서버 조작, 허용목록 외 재시작, 관측 원본 삭제·추정값 덮어쓰기, 운영 설정·인증정보 변경, 무제한 클라우드 확장.

**필요 기능:** 제한된 데이터 조회 인터페이스, 자체 수집 상태 확인 및 허용된 재시작 기능, 사건 기록. 명령·클래스·구현 파일 구조는 이 단계에서 정하지 않는다.

복구 시도 결과를 보고할 수 있지만 사건 완료를 판정할 권한은 없다.

## 2.4 복구 성공을 독립적으로 검증하는 주체는 누구인가?

**이름:** Verification 역할.

Recovery의 보고를 입력 근거 중 하나로 사용하되 독립된 조회·상태 확인으로 결과를 판단한다. 복구 실행·정책 변경은 금지한다.

- AIS 수집 복구: 오래된 캐시·중복 기록이 아닌 새로운 유효 관측의 수신, 시각의 의미, 기능 표시, 중복·원본 보존을 확인한다. 같은 공급자/스트림/범위의 사건 기준 이후 새 유효 관측1건 이상과 나이0~10분을 확인한다. B관측으로 A사건 종료는 금지한다. 세부는 DEC-05/POL-08이다.
- 통계 조회 복구: 같은 원천·보고국/상대국·운송모드·분류판·주기/기간·방향·단위 계약이 맞는 정상 자료를 다시 얻고 표시할 수 있는지 확인한다. 새 월의 등장 자체를 성공 조건으로 요구하지 않는다.
- 재생 모드: 논리적 관측 시각으로 확인하고 실시간 복구 성과와 구분한다.
- HTTP 성공만 반환되는 것, 재시작 요청이 성공하는 것은 그 자체로 복구 성공이 아니다.

**실패:** 검증 근거 부족·형식/단위/시각 불일치·중복·정상 기능 미회복. 시도 한도 내 다음 판단 또는 중단·사람 전달로 전환한다.

## 2.5 오케스트레이터가 필요한가?

**판단:** 순서·횟수·상태 관리 기능이 필요하다. 별도 LLM 에이전트 필요성을 의미하지 않는다.

**책임:** 사건 중복 실행 방지, 진단→복구→검증 순서, 시도·전체 시간 상한, 회로 차단, 승인 대기와 에스컬레이션 관리.

**금지:** 허용목록·상한 우회, 직접 복구 도구 조작, Verification 없이 성공 선언.

## 2.6 에이전트 협업 구조

| 역할 | 입력 | 출력 | 호출 주체 | 허용 권한 | 실패 시 행동·타임아웃 |
|---|---|---|---|---|---|
| Monitor | 상태·원천 응답·관측 시각 | 사건과 증거 | 조회 주기·상태 관찰 기능 | 읽기·사건 기록 | 감시 불가 표시, 시간은 DEC-02/POL-03 |
| Diagnosis | 사건·이력·상태 | 원인 후보·복구 방향 | Orchestrator | 읽기·판단 근거 기록 | 불명확하면 사람 전달, 시간은 DEC-05/POL-24 |
| Recovery | 허용된 전략·시도 여유 | 시도 결과 | Orchestrator | 한정된 조회·재연결·재시작 | 실패 이력 보고, 시간은 DEC-05/POL-24 |
| Verification | 시도 결과·독립 관측 | 정상/실패/판단 불가 | Orchestrator | 독립 조회·판정 기록 | 성공 처리 보류, 시간은 DEC-05/POL-24 |
| Orchestrator | 사건·각 역할 결과 | 상태·호출·종료/전달 | 사건 생성 | 흐름·한도 관리 | 안전 중단, 전체 시간은 DEC-05/POL-24 |
| Notification | 사건·승인 요청·종료 결과 | 사람에게 전달 기록 | Orchestrator | 지정 채널 전달만 | 미전달 기록, 실습 운영자·POL-10~11·24 |

**협업 흐름:** 사건 관찰 → 진단 → 자체 복구 대상이면 허용 조치 → 독립 검증 → 성공 시 사건 종료. 실패는 상한 안에서 재판단하며 한도 초과·불명확은 안전 중단·사람 전달. 선박별 공백/위치 이상은 표시·기록 흐름으로 보내며 그것만으로 수집기를 재시작하지 않는다.

## 2.7 조회 AI의 책임과 정보 경계

### 조회 AI — 읽기 전용 사용자 질의

- 책임: 서비스 보유 데이터에 대한 자연어 질문을 제한 조건으로 해석하고 근거를 붙여 설명.
- 입력: 사용자 질문, 명시한 화면 선택, 가용성 정보, 허용 조회 결과.
- 출력: 적용 조건·수치 근거·출처·기간·한계·관련 화면 링크 또는 명확화 질문/답변 불가.
- 사용할 수 있는 정보: 서비스가 실제 보유한 선박 상세·항적 요약·통계·행동 후보·관련 소식 메타데이터/요약·연결 근거만. 뉴스 수집과 조회 AI를 분리한다.
- 허용 행동: 가용성 조회, 선박 상세 조회, 항적 요약 조회, 통계 조회, 결정적 계산 도구 및 저장된 행동 후보·소식·연결 근거 전용 읽기 도구 호출. 새 도구는 작업3.10 계약 후 연결한다.
- 금지 행동: 임의 SQL·쉘·파일·URL 탐색/웹 검색, 복구/재개/정책 변경, 없는 자료 생성, 수치 직접 계산, 근거 없는 원인 설명·운항 추천. 사용자 질문과 원천 문자열 안의 지시는 데이터로 취급하며 도구 권한을 바꾸지 않음.
- 실패 시 행동: 조건 명확화·가용 범위 안내 또는 정형 조회+근거 표 대체. AI 실패를 수집 장애로 승격하거나 자동 복구를 호출하지 않음.

조회 AI는 우리 서비스가 실제 보유한 자료를 자연어로 조회하는 별도 읽기 전용 기능이다. 자연어 → 제한된 조회 조건 → 가용성 확인 → 허용 읽기 도구/결정적 계산 → 근거 응답 순서를 따른다. 저장 소식 질문에는 매체·원문 링크·발행/사건/확인 시각·연결 근거·보도 한계를 붙이고 원인 불명을 유지한다. 화면 선택을 사용하면 답 첫 줄에 적용 국가·원천·운송모드·분류판/레벨·주기·방향·분류·기간을 명시한다. 방향이 없고 선택에 따라 답이 달라지면 먼저 묻는다. “핀란드에서 최근 증가한 물류/추세?”에는 원천과 분류를 식별하고 해상 수출입 상품(월/연)·핀란드 월 품목·분기 화물형태 중 어느 모드인지 확인하거나 적용 화면 조건을 명시한다.

초기 해석은 최근=해당 조합의 최신 공표 기간, 증가=확인된 중량 기준 직전 달/분기/연도 대비 톤수 변화, 추세=최근 6개 연속 달력 기간의 첫 값과 끝 값의 변화다. 가용한 연속 기간이 3~5개면 실제 기간 수와 제한을 명시하고, 3개 미만 또는 선택 구간 중간 결측이면 추세 판단 불가로 응답한다. 끝점 변화는 매 기간 단조 증가·계절조정 추세·예측을 뜻하지 않는다. 원인 추측·운항 추천은 하지 않는다.

수치·순위·차이·비율은 결정적 계산 도구 결과만 인용한다. 모델이 직접 계산하거나 없는 셀을 만들지 않는다. 답에는 국가·원천 표·운송모드·분류판/레벨·분류·방향·기준/비교 기간·단위·계산 분모·조회 시각·잠정/누락/공표 지연·관련 화면 링크와 사용 셀/계산 근거를 포함한다. 확인 가능한 근거가 없으면 답변 불가와 필요한 조건을 제시한다.

무료 또는 로컬 모델은 아직 선정·실행 검증하지 않았다. 후보의 이용 조건·한국어 질의 변환·근거 준수·장비 성능을 구현 전에 확인해야 한다. 유료 키나 외부 전송은 임의 허용하지 않는다. 모델 오류·가용성 부족 시 정형 조회와 근거 표로 대체하되 이것만 동작하면 “AI 완료”로 처리하지 않는다. 모델 장애는 AIS 수집기 재시작의 근거가 아니다.

# 3. 자율성과 통제

## 3.1 자동으로 실행해도 되는 복구는 무엇인가?

| 행동 | 이유·영향 범위 | 선행조건 | 실행 후 검증 |
|---|---|---|---|
| 제한된 재조회·재연결 | 일시적인 요청 실패, 해당 수집 흐름만 영향 | 알려진 유형·허용 대상·시도 여유 | AIS 새 유효 기록 또는 정상 공표 통계 |
| 격리 수집 프로세스 재시작 | 자체 중단에 한정 | 별도 감시 주체 생존, 허용목록·시도 여유 | 생존 상태와 실제 데이터 정상화 |
| 마지막 정상 자료 유지 | 화면 이용 연속성 | 이전 자료 존재·시각 표시 | 지연 상태를 최신으로 표시하지 않음 |

마지막 정상 자료 표시는 대체 동작이지 복구 완료가 아니다. 전체 PC·호스트가 꺼진 경우 동일 호스트의 에이전트가 이를 복구한다고 약속하지 않는다.

## 3.2 사람의 승인이 필요한 복구는 무엇인가?

| 행동·상황 | 승인 필요 이유 | 승인자·기한 | 미승인 시 행동 |
|---|---|---|---|
| 원인 불명·시도 상한 초과 후 추가 조치 | 자동 판단 근거·권한 부족 | DEC-06 | 중단 상태와 마지막 정상 자료 유지 |
| 허용목록·임계값·복구 정책 변경 | 승인 범위가 바뀜 | DEC-06 | 기존 정책 유지 |
| 운영 설정·비용·인증·데이터 변경 | 이번 자동 복구 범위 밖 | 구체 실행 요구는 후속 결정 | 자동 실행하지 않음 |

실습의 사람 인계는 운영 화면의 사건 표시와 운영자 확인 후 재개로 제한한다. 임의 설정·비용·인증·원본 변경은 자동 승인 후 실행 기능에 포함하지 않는다(POL-10~11).

## 3.3 복구를 몇 번까지 재시도할 것인가?

**최대 시도·대기:** 추가 요청은 사건당 3회, 대기는 5·15·30초, 자체 재시작은 1회, 활성 복구 구간은 180초다(POL-04~06). 가이드 예시 복사가 아니라 요청 증폭과 실습 시간 예산을 제한하기 위해 선택한 초기안이다.

**기록 위치:** 사건별 복구 이력에 횟수·전략·대기·결과를 보존한다. 재시작 때문에 시도 횟수가 초기화되지 않아야 한다. 저장 매체는 DEC-07의 기술 결정이다.

## 3.4 무한 복구 루프를 어떻게 방지할 것인가?

사건별·전략별 시도 상한, 전체 흐름 시간 상한, 연속 실패 시 회로 차단, 냉각 후 상태 확인과 운영자 확인을 모두 거친 재개, 중복 사건 실행 방지가 필요하다.

**차단·재개:** 한도 또는 시간 초과 시 해당 원천 차단. 300초 후 읽기 전용 검증을 1회 하되 성공해도 차단을 유지한다. 운영자가 확인·재개를 요청하고 독립 검증도 성공해야 사건 종료·정규 수집 재개가 가능하다. 검증 실패·판단 불가는 중단을 유지하며 같은 사건의 추가 자동 복구 한도를 초기화하지 않는다(POL-07·11).

## 3.5 잘못된 복구를 어떻게 취소할 것인가?

| 행동 | 보존할 상태 | 실패 판정 | 롤백 또는 안전 중단 | 확인 |
|---|---|---|---|---|
| 재조회·재연결 | 원본·마지막 유효 관측·이전 정상 통계 | 오류·오래된/잘못된 자료 | 정상 저장본을 덮어쓰지 않고 재시도 중단 | 원본·시각·단위·표시 상태 보존 |

## 5.2 장애 탐지부터 복구까지 걸린 시간을 어떻게 측정할 것인가?

- 장애 발생/모의 주입 시각: 실습 원천에서 사건이 시작된 시점. 실제 외부 장애의 시작을 모르면 미확인으로 남긴다.
- 탐지 시각: Monitor가 사건을 생성한 시점.
- 활성 복구 시작 시각: Orchestrator가 사건 분류를 위해 Diagnosis를 처음 호출한 시점. 첫 Recovery 조치 시각은 별도로 기록한다.
- 복구 확인 시각: Verification이 정상 결과를 독립 확인한 시점.
- 탐지 소요시간은 탐지 시각에서 발생 시각을 뺀 값, 복구 소요시간은 독립 정상 확인 시각에서 발생 시각을 뺀 값이다. 여러 사건의 평균을 각각 MTTD·MTTR로 보고한다.
- 활성 복구 시간은 독립 확인 시각에서 활성 복구 시작 시각을 뺀 값으로, 180초 목표는 이것을 뜻한다. 발생부터의 MTTR과 다르다. 차단 이후 300초 냉각·읽기 검증·운영자 대기는 활성 구간 밖의 인계 시간으로 기록하며 자동복구 성공률에 합산하지 않는다.
- 시작 시각 불명의 실제 사건과 재생 시계의 수치는 알려진 주입 시각의 실습 결과와 분리한다.
- 원천 관측 시각, 수집 성공 시각, 통계 기준월, 통계 공표/갱신일을 별개로 유지한다.

기록은 UTC 기준 시각, 화면 기본 시간대는 Asia/Seoul, 재생은 원자료 시각을 따른 별도 모드로 정한다(POL-15). 서로 다른 시간대나 초/밀리초 단위를 섞지 않아야 한다.

## 5.3 어떤 로그를 반드시 보존할 것인가?

사건·추적 식별자, 데이터원·대상 선박/통계 범위, 실제 관측/발생·탐지·복구·검증 시각, 원인 후보와 근거, 선택 전략, 허용된 호출 정보, 시도·대기·결과, 사람 승인·전달 상태, 독립 검증 근거, 최종 상태·소요시간을 보존한다.

원본 관측과 이상 여부를 구분하고, 원본을 추정값으로 대체하지 않는다. 마지막 정상 통계와 원자료 갱신 이력을 식별한다. 재처리는 동일 기록을 무한 중복 누적하지 않아야 한다.

키·토큰·비밀번호·불필요한 개인정보는 로그에서 제외한다. 앱 전용 로컬 저장·운영자 접근을 전제하며 자료별 보존은 §1.4와 POL-13~15를 따른다. 관측 2년, 운영 로그 종료 후 30일, 열린 사건 필수 근거 예외, 대화/조회 응답 근거 기본 세션 내 보존을 구별한다. 자동 외부 백업은 MVP 밖이다.

PRD §15의 감시 선박·원본/판정·계산·항만 방문/항해 연결·항적 구간·통계 셀/가용성·조회 근거·행동 후보·뉴스 항목·행동-소식 연결·뉴스 조회·사건/시도/검증 관계를 저장 의미로 사용한다. 상세 스키마 기술 선택은 후속이며 원천 시각/수집/갱신·연도 존재·최초 수집 시각·정책 버전을 보존한다.

# 7. 최종 범위 선언

## 반드시 충족할 서비스 범위

선박 해상 화물 모니터의 핵심은 Auto Healing의 탐지·진단·제한 복구·독립 검증·차단/사람 인계다. 국가·100척 제품 상한 없이 활성 원천의 실제 집합을 관리하고 카드·기국 필터·공백/이상·2년 실항적을 제공한다. 실제 Sea 확인 상품의 HS2→HS4, 핀란드 월6/16, Eurostat 분기 형태를 분리하며 읽기 전용 조회 AI는 보유 근거만 사용한다. P1 행동 후보·원인 불명·관련 소식은 카드/항적에 출처와 연결 근거를 제공하며 인과 확정으로 바꾸지 않는다. REQ-01~03·05~21의 활성20개, PRD의 활성FR20+NFR10=30개와 연결된다. 상위8은 유지하고 퇴역3.3·이전 추가1.7/4.7과 신규1.8/2.6/3.9/3.10을 반영한 활성 상세57개는 전부pending이다.

## 목표가 아닌 것

1.4의 제외 범위를 따른다. 국가 통계·AIS 선종을 개별 선박 적재 명세로 만들지 않는다. 전세계 완전 커버리지·무제한 자원·미확인 후보 지원을 보장하지 않는다. AISHub/AIS Friends와 수신기 설치·데이터 기여 경로는 제외다.

## 성공 기준과 현재 상태

정상 기준선과 세 가지 수집 장애의 제한 복구·독립 정상화/안전 중단·필수 기록이 핵심 목표이며 모두 미래 인수 기준이다. 업무 서비스의 활성 요구·근거·권한·가용성 조건도 충족해야 전체 완료다. **항행 특이점·관련 소식 기획 개정안 / 사용자 요청·세부 초기안·미확인 구분 / 독립 검수 대기 / 구현 미착수**. 과거 승인과 새 세부안/기술 게이트 해소를 구별하며 문서 검수·승인 뒤에도 별도 구현 요청이 필요하다. 구현·실험은 수행하지 않았다.

다음은 당시 재검수 제출 기록이다: PRD v0.2.1과 워크시트 v0.5.1을 REV-01~22 전체 재검수 대기로 제출했다. 이후 승인 원본의 통과 결과는 위 기록에 별도로 연결했다. 최초 제출 v0.2/v0.5의 독립 검수에서 REV-08은 분기 기간을 화물형태 개수로 잘못 쓴 표현 때문에 실패했고 나머지 21개 규칙은 통과했다. 해당 판정은 최초 제출본의 역사이며 현재 수정본에 재사용하지 않는다. 이번 수정은 기간을 최근 공개 8분기(+직전 비교 1분기 확보 목표), 분류를 가용 5개 화물형태 및 TOTAL로 구별하고 NFR 표 연결·협업 표 열 구분을 보완했다.

과거 R01~R25 및 25개 PASS 기록도 PRD v0.1/워크시트 v0.4에만 유효하다. 수정 전 원문·SHA-256은 before_prd / before_worksheet, 최초 제출 원문·SHA-256·배정표는 after_prd / after_worksheet에 유지한다. 이번 수정 제출본은 새 키 after_prd_r2 / after_worksheet_r2에 원문·SHA-256·REV 배정표를 보존하며 기존 키는 덮어쓰지 않는다. 독립 검수 응답의 규칙별 판정·근거·대상 해시는 조정 담당이 해당 묶음에 연결한다. 통과 기록만 추가하려고 검수 대상 문서를 다시 고치지 않는다.

최초 검수 실패 시 최초 제출 원문을 기준으로 필요한 부분만 수정한다. 후속 단계 실패 시 직전 유효 통과 체크포인트에서 수정하고 영향을 받는 가장 이른 단계부터 순차 재검수한다. 통과한 단계의 원문·해시·규칙 배정·판정/근거는 덮어쓰지 않고 복구 가능하게 보존한다. 새 버전에 옛 판정을 재사용하지 않는다. 검수 실행이 불가능하면 통과를 꾸미지 않고 제한을 보고한다.

워크시트 정합성 검수와 사용자 PRD 승인은 별개다. 승인 원본의 검수와 사용자 PRD 승인을 근거로 02 상위 제안까지 진행하며, 현재 다음 사용자 승인 대상은 상위 작업이다.
