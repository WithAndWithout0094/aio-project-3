## 2. 프로젝트 개요

사용자가 핀란드 해역에서 확보한 선박 관측과 핀란드의 들어오고 나가는 해상 화물을 조회하면, 서비스는 선박의 관측 공백·위치 이상을 표시하고 월별 품목군의 물량·비중·변화를 반환하며, 수집 장애에는 한정된 복구와 독립 검증을 수행한다.

제품은 브라우저에서 사용하는 교육용 웹앱이다. 최초 사용 범위는 로컬 Windows 11 PC 한 대와 최신 안정 Chrome·Edge다. 공개 API 이용과 로컬 영속 저장을 기본으로 하고, 공개 배포·클라우드·다중 사용자 계정은 이번 MVP에서 제외한다. 일반 사용자·기업·개인사업자를 장래 사용자로 삼되 실습에서는 팀이 그 사용 흐름을 시연한다.

업무 기능은 **선박 신호 공백·이상 탐지** 하나다. 해상 화물 통계는 같은 제품의 조회·집계 화면이다. Auto Healing의 탐지·진단·복구·검증은 책임을 나누는 결정적 워크플로로 설계하며 각각 별도 LLM이나 유료 AI를 요구하지 않는다.

## 3. 문제 정의

지도에 남은 마지막 좌표만으로는 선박이 현재도 그 위치에 있는지, 새 신호가 없는지, 수집기가 멈췄는지 알기 어렵다. 위치가 비정상적으로 튀는 관측까지 정상 항적으로 처리하면 평균 속도와 이동 범위가 왜곡된다. 사용자는 관측 사실·계산값·가정에 따른 추정을 구별해야 한다.

핀란드로 들어오고 나가는 품목군의 규모와 증감을 보려면 월별 통계의 분류·단위·누락 상태를 이해해야 한다. 이 통계는 개별 선박의 현재 적재 품목을 알려주지 않는다. 서로 다른 자료를 하나의 화물 추적 결과처럼 합치지 않는 것이 핵심이다.

수집 요청 오류나 자체 수집기 중단이 발생하면 운영자는 실패 원인과 조치 이력을 확인하고 재조회·재시작 뒤 실제 자료가 정상화됐는지 확인해야 한다. 현재 사용자의 실무 대응 경험과 수동 소요시간은 제공되지 않았으므로 절감률을 만들어 쓰지 않는다. 교육 실습의 영향은 자료 지연과 분석 중단 수준의 중간 심각도이며, 항해 안전·실제 물류 의사결정 보장을 목표로 하지 않는다.

## 7. 정상 서비스 시나리오

### 화면 구조와 공통 상태

상단에는 **선박 모니터링 / 해상 화물 통계** 두 진입점을 둔다. 선박 화면은 지도·선박 목록·기국 필터·자료 상태, 화물 화면은 핀란드·입출 방향·기준월·품목 목록·라인 그래프로 구성한다. 운영 사건 화면은 실습 담당자만 사용하는 별도 경로다.

정상 선박은 유효 진행 방향의 색 있는 화살표, 미수신은 회색과 상태 문구, 이동 범위는 투명도가 높은 푸른 부채꼴로 표현한다. 방향이 없으면 방향 없는 표식을 사용한다. 색만으로 의미를 전달하지 않고 목록·텍스트로 같은 내용을 확인하게 한다. 팝업·필터·품목 펼치기는 키보드로 조작하고 팝업 닫기 후 선택 항목으로 초점을 돌린다.

| 공통 상태 | 화면 동작 |
|---|---|
| 최초 로딩 | 불러오는 자료와 진행 상태 표시; 이전 자료가 없으면 빈 틀을 정상 값처럼 채우지 않음 |
| 조회 결과 없음 | 실제 확보 수 0·자료 없음과 마지막 시도 시각 표시 |
| 일부 필드 부족 | 항목별 데이터 부족과 사유; 다른 유효 필드는 유지 |
| 갱신 실패·캐시 존재 | 마지막 성공 자료·관측/기준 시각·지연 또는 복구 상태 함께 표시 |
| 지도 실패 | 선박 목록·시각·상태·팝업 정보 유지, 지도 재시도 안내 |
| 재생 모드 | 모의/재생 배지·논리적 기준 시각 표시; 실시간 자료와 섞지 않음 |

### S-01 선박과 관측 공백 탐색

사용자가 선박 화면에 진입하면 최초 최신 유효 관측 순으로 최대 100척을 선정한다. 같은 시각이면 식별번호 순으로 고른다. 감시 목록은 브라우저 새로고침이나 수집기 재시작으로 바뀌지 않게 보존한다. 감시 대상이 사라져도 다른 선박으로 자동 교체하지 않는다. 자료가 100척보다 적으면 확보된 수만 표시한다. 기국 필터는 이 감시 집합에 적용하며 전 세계 해당 기국 전체를 뜻하지 않는다.

5분마다 새 자료를 조회하고 마지막 신규 원본 시각과 마지막 유효 위치 시각을 구분한다. 미수신 선박을 선택하면 팝업과 조건부 부채꼴을 보여준다. 유효 관측을 다시 받으면 추정을 닫고 실제 관측으로 돌아가며 공백 사건은 보존한다. 위치 도약 후에는 POS-03의 두 후보 조건을 거쳐 추적을 재개한다.

### S-02 선박 상세 확인

사용자는 선박명·식별번호, 기국, 현재 위치 국가, 출발·도착 국가, 적재 화물, 최근 관측 속도 평균, 특이사항과 각 항목의 출처·시각을 확인한다. 이전/다음 항구만 확인되면 그 이름으로 표시한다. 현재 해역 경계 근거·정확한 출발/도착 연결·개별 적재 자료를 확보하지 못하면 데이터 부족을 표시하는 것이 정상 결과다. 수집 위치가 핀란드라는 이유로 기국이나 현재 국가를 정하지 않는다.

### S-03 해상 화물 탐색

국가 목록은 핀란드 하나다. 사용자는 들어오는 화물 또는 나가는 화물과 공개 기준월을 선택한다. 상대국 전체 합계 기준을 고정한다. 큰 분류를 누르면 공식 품목군까지 한 단계 펼친다. 선택한 분류·품목의 최근 공개 24개 달력월 톤수 라인 그래프와 선택 월의 전체 대비 비중·전월 차이·증감률을 본다.

최신 공개 기준월을 끝으로 24개월을 표시하고 첫 달 전월 비교용 1개월을 추가 보관한다. 중간 누락은 건너뛰어 다른 달로 대체하지 않는다. 공개 자료 확인은 하루 1회이며 새 달이 아직 공표되지 않은 것은 장애가 아니다.

### S-04 정상 수집·저장

수집 자료는 원본과 계산·판정을 구분해 저장한다. 동일 관측 재조회는 중복 누적이나 관측 시각 갱신으로 처리하지 않는다. 관측·사건은 30일, 통계는 표시 24개월+비교용 1개월을 기본 보관하며 열린 사건 근거는 종료 전 유지한다. 마지막 정상 자료를 표시하는 것만으로 장애를 해결했다고 판단하지 않는다.

## 8. 장애 시나리오

모든 재현 방법은 **후속 구현 단계의 격리 실습 설계**다. 실제 제공자 API에 오류를 유발하거나 오늘 프로세스를 중단하지 않는다.

| ID·장애 | 발생 위치·탐지 신호 | 사용자·운영 영향 | 안전한 재현 조건 | 예상 결과 |
|---|---|---|---|---|
| F-01 HTTP 5xx | 모의 원천 응답의 5xx·요청 시각 | 갱신 실패·자료 지연 | 격리 모의 응답을 정해진 횟수만 5xx 후 정상으로 전환 | 제한 재조회 후 독립 정상 확인 |
| F-02 응답 타임아웃 | 요청 후 10초 이내 응답 미완료 | 로딩 지연·자료 공백 | 모의 응답만 10초를 넘게 지연한 뒤 후속 응답 정상화 | 취소/실패 기록·제한 재연결·검증 |
| F-03 자체 수집기 중단 | 별도 감시의 10초 간격 생존 점검 3회 실패 | 관측 갱신 중단 | 격리된 허용목록 수집기만 중단; 감시·판정 주체는 유지 | 재시작 최대 1회·생존과 데이터 정상화 검증 |
| F-04 개별 신호 공백 | 해당 선박 신규 원본 관측 15분 이상 없음 | 회색·위치 불확실 | 재생에서 한 선박의 신규 관측만 끊고 다른 선박은 정상 유지 | 공백 표시·조건부 부채꼴; 수집기 재시작 안 함 |
| F-05 위치 도약 | 좌표·시각 유효성 및 POS-02 기준 | 항적·평균 왜곡 우려 | 재생에서 특정 선박에 도약 후보·이후 연속 후보 공급 | 의심 관측 격리·원본 보존·조건 충족 시 추적 재개 |

F-01~03의 확장 조건으로 계속된 실패·한도 소진·검증 불가·중복 사건을 다룬다. 최신 통계 월 미발표는 F-01~03에 속하지 않는다. 제공자가 정상 응답을 주지만 모든 관측이 오래된 경우는 신선도 이상으로 기록하고 원인을 단정하지 않는다. 이 증거만으로 프로세스를 재시작하거나 데이터 복구 성공을 선언하지 않는다.

## 9. 멀티 에이전트 구성

업무 에이전트는 신호 공백·이상 탐지 하나이며, 아래는 복구 안전성을 위한 역할 경계다. 하나의 프로그램 안에서 규칙 기반 기능으로 구현할 수 있다. 실제 프로세스 분리 여부는 후속 기술 결정이지만 자체 수집기가 중단돼도 감시·판정이 작동해야 한다.

### Monitor

- 책임: 수집 오류·생존·관측 시각·위치 이상 신호를 관찰하고 사건 후보 생성.
- 입력: 응답 코드·지연, 생존 상태, 신규 관측·통계 공표 상태.
- 출력: 사건 ID·추적 ID·유형 후보·대상·탐지 시각·증거.
- 사용할 수 있는 정보: 원천 응답, 최근 관측, 허용된 생존 상태.
- 허용 행동: 읽기·사건 기록; 5분 조회와 10초 생존 점검.
- 금지 행동: 재시작·설정 변경·복구 성공 선언.
- 실패 시 행동: 감시 불가를 표시·기록하고 정상 상태로 가장하지 않음.

### Diagnosis

- 책임: 요청 실패·자체 중단·관측 품질 사건·원인 불명을 근거에 따라 구분.
- 입력: Monitor 사건, 상태·응답·관측 이력.
- 출력: 분류·근거·불확실성·허용 전략 또는 사람 인계.
- 사용할 수 있는 정보: 해당 사건 증거와 승인 정책.
- 허용 행동: 읽기·분류·근거 기록.
- 금지 행동: 직접 복구·허용목록 수정·신호 공백 원인의 단정.
- 실패 시 행동: 5초 내 판정하지 못하거나 증거가 충돌하면 판단 불가로 중단·인계.

### Recovery

- 책임: Orchestrator가 승인 정책 안에서 선택한 복구 조치 수행.
- 입력: 사건 ID, 허용 전략·대상, 잔여 횟수·시간.
- 출력: 시도 ID·시작/끝 시각·조치 결과·오류.
- 사용할 수 있는 정보: 허용된 수집원·수집기·사건 한도.
- 허용 행동: 제한 재조회/재연결·허용 수집기 재시작.
- 금지 행동: 사건 성공 판정, 임의 명령·다른 프로세스 제어·원본 수정.
- 실패 시 행동: 실패 결과만 보고; 스스로 재귀 호출하지 않음. 요청은 10초, 재시작 상태 확인은 30초 상한.

### Verification

- 책임: 복구 실행 결과를 별도의 읽기 관측으로 검증.
- 입력: 사건 기준 관측, 시도 결과, 독립 확인 자료.
- 출력: 성공/실패/판단 불가·근거·확인 시각.
- 사용할 수 있는 정보: 원천의 새 관측·정상 통계, 자체 생존·저장·표시 상태.
- 허용 행동: 독립 읽기와 검증 기록.
- 금지 행동: 복구 조치·정책 변경, Recovery의 자기보고나 캐시만으로 성공 선언.
- 실패 시 행동: 30초 내 근거 확보가 안 되면 판단 불가; 중단·인계하며 성공으로 기록하지 않음.

### Orchestrator

- 책임: 중복 사건 병합, 순서·상태·횟수·시간·차단·재개 통제.
- 입력: 사건과 각 역할 결과, 운영자 확인.
- 출력: 역할 호출·상태 전이·종료/차단·전달 요청.
- 사용할 수 있는 정보: 열린 사건·영속 한도·승인 정책·독립 판정.
- 허용 행동: 진단→조치→검증 호출, 한도 관리, 검증 결과에 따른 종료.
- 금지 행동: 직접 복구 도구 조작, 한도 초기화 우회, 검증 없는 성공 선언.
- 실패 시 행동: 180초 활성 기한 도달 또는 상태 불일치 시 조치 중단. 재시작 후에도 이전 사건·횟수를 이어받음.

### Notification

- 책임: 로컬 운영 사건 화면에 필요한 인계와 결과를 지속 표시.
- 입력: 사건 상태·근거·시도·검증 결과·운영자 확인 필요 여부.
- 출력: 전달/확인 상태와 기록.
- 사용할 수 있는 정보: 해당 사건의 전달용 요약.
- 허용 행동: 로컬 화면·기록 갱신.
- 금지 행동: 외부 이메일·문자 발송, 자동 승인·복구 실행.
- 실패 시 행동: 5초 내 전달 기록이 안 되면 미전달 상태를 보존. 사람이 확인했다고 표시하지 않음.

## 10. 에이전트 협업 흐름

정상 흐름은 **관찰 → 사건 생성 → 진단 → 허용 조치 → 독립 검증 → 종료 기록**이다. 관측 공백·위치 이상은 표시·이력 흐름으로 분기한다. 원인 불명이나 근거 부족은 자동 변경 없이 사람에게 인계한다.

| 상태 | 진입 조건·다음 동작 | 종료/다음 상태 |
|---|---|---|
| 감시 중 | 정상 조회·생존 확인·관측별 판정 | 오류 증거가 있으면 탐지 |
| 탐지·진단 | 같은 수집원의 열린 사건에 증거 합침; 최초 Diagnosis 호출을 활성 시작으로 기록 | 알려진 복구 대상→조치, 자료 사건→표시, 불명→인계 |
| 조치 | 잔여 한도·기한 확인 후 Recovery 호출 | 완료 보고→독립 검증, 실패→남은 정책 또는 차단 |
| 독립 검증 | 신규 유효 자료·원천 의미·생존·보존 상태 확인 | 성공→정상 종료, 실패/판단 불가→남은 한도 또는 차단 |
| 회로 차단 | 정규 수집 요청·변경 조치 중지, 마지막 자료·실패 근거 표시 | 300초 뒤 단 한 번 30초 이내 읽기 확인 |
| 회복 관측/인계 대기 | 냉각 후 확인 성공도 회로는 유지; 실패·불가도 유지 | 운영자 확인·재개 요청 대기 |
| 운영자 재개 확인 | 원인·수동 조치 확인 후 30초 한도 독립 읽기 검증 | 성공→사건 종료·차단 해제, 실패/불가→같은 사건 중단 유지 |

닫히지 않은 사건의 시도 한도는 정규 스케줄·브라우저 새로고침·수집기 재시작·냉각·운영자 버튼으로 초기화하지 않는다. 정상 종료 후 새 장애 증거가 생긴 경우에만 새 사건과 한도를 부여한다.

활성 구간은 최초 Diagnosis 호출부터 180초 이내다. 냉각 후 읽기 확인과 운영자 대기는 차단 이후의 별도 인계 구간이다. 이 시간을 숨겨 활성 복구 성공처럼 집계하지 않는다. 대기 중 외부 상태가 저절로 회복돼도 운영자 확인 전 정규 수집은 재개하지 않는다.

## 11. 장애별 복구정책

### 공통 상한과 독립 성공 조건

| 정책 | 초기 기준과 이유 |
|---|---|
| POL-03 요청·생존 | 원천 요청 10초 제한; 생존 점검 10초 간격 3회 연속 실패. 자료 갱신 5분과 자체 프로세스 탐지를 분리 |
| POL-04 재시도 | 사건당 최초 정규 요청 외 추가 재조회/재연결 최대 3회; 각각 시작 전 5·15·30초 대기. 제공자의 더 긴 대기 요구가 우선이며 활성 기한을 넘으면 중단 |
| POL-05 재시작 | 사전 허용된 자체 수집기만 사건당 1회. 개별 선박 공백·위치 도약만으로 재시작하지 않음 |
| POL-06·24 시간 | 최초 Diagnosis 호출부터 정상 확인 또는 차단까지 180초. 진단 5초·요청 10초·재시작 상태 확인 30초·검증 30초·전달 기록 5초가 모두 이 기한에 포함 |
| POL-07·11 차단 | 상한 도달 후에도 정상화가 확인되지 않거나 활성 기한 도달 시 차단. 300초 후 읽기 확인 1회. 성공 여부와 무관하게 운영자 확인+새 독립 검증 성공 전 차단 유지 |
| POL-08 AIS 검증 | 자체 생존 정상이며 사건 전 기준보다 새롭고 관측 나이 0~10분인 유효 관측을 감시 대상 중 1건 이상 독립 확인. 시각·단위 오류는 배제. 표시·보존 정상도 확인 |
| POL-09 통계 검증 | 이미 공개된 기간의 자료를 다시 읽어 품목·입출 방향·톤 단위·기간·누락 의미 및 표시·보존을 확인. 새로운 월의 공표를 요구하지 않음 |

## 12. 자율성과 Human-in-the-loop

| 구분 | 행동·조건 |
|---|---|
| 자동 실행 가능 | 알려진 요청 실패의 제한 재조회/재연결, 증거가 있는 허용 수집기 중단의 1회 재시작, 독립 검증, 마지막 정상 자료 유지, 규정된 앱 보존기간 정리 |
| 사람 확인 필요 | 회로 차단 후 원인·수동 조치 확인 및 재개 요청, 임계값·허용목록·복구 정책의 변경 결정 |
| 자동 실행 금지 | 임의 쉘 명령·외부 서버/선박 조작·허용목록 밖 재시작·원본 좌표 변조·운영 데이터 삭제·인증정보 변경·비용 확대·자동 승인 |

운영자 확인은 같은 사건의 시도 예산을 추가하는 버튼이 아니다. 확인 이후 읽기 검증에 실패하면 중단 상태를 유지한다. 정책 변경이나 외부 조치는 이 MVP의 자동 실행 기능이 아니며, 승인 기록 없이 적용된 것으로 처리하지 않는다.

화면에 사건 상태·원인 후보·불확실성·시도 횟수·기한·검증 결과·필요한 사람 판단을 남긴다. 전달 실패와 사용자의 미확인을 구분한다. 운영자는 실습 팀 담당자 1명이며 실명 지정은 후속 실습 준비 사항이다.

MQTT 등을 후속 선택하면 그 원천의 초 단위 전체 시각을 별도 변환해야 한다. 수집 시각·메타데이터 갱신 시각은 위치 관측 시각과 다르다. SOG 102.3, COG 360 등 원천의 미제공 값은 결측 처리한다. ### FR-001 선박 감시 대상과 수집

- 설명: 확보된 핀란드 AIS에서 최대 100척을 고정 감시한다. REQ-01·15.
- 입력: 유효 관측·식별번호·원천 시각, 기존 감시 목록.
- 기대 동작: POL-01에 따라 최초 선정·영속 보존하고 5분마다 조회한다. 수집 시각과 실제 관측 시각을 구별한다.
- 예외 상황: 100척 미만·0척이면 실제 확보 수를 표시한다. 중복·과거·시각 오류 자료는 현재 상태를 덮어쓰지 않는다.
- 인수조건: 표시 대상은 100척 이하이며 새로고침·재기동·개별 공백으로 목록이 교체되지 않는다. 동일 원본의 재조회로 최신성이 개선되지 않는다.

### FR-002 신호 공백과 재관측

- 설명: 선박별 공백을 수집원 장애와 구분한다. REQ-03·10.
- 입력: 신뢰 가능한 마지막 신규 원본 시각·마지막 유효 위치·현재 시각.
- 기대 동작: GAP-01~02 기준으로 최신/지연/미수신과 경과 시간을 표시한다. 미수신은 회색으로 나타낸다.
- 예외 상황: 신규 원본은 있으나 위치가 이상하면 위치 이상으로 표시한다. 시간이 잘못된 원본은 공백 종료 근거가 아니다.
- 인수조건: 10분·15분 경계에서 지정 상태가 다음 조회에 반영되고, 유효 재관측 후 표시가 복귀하며 공백 이력이 유지된다.

### FR-003 위치 유효성과 도약 의심

- 설명: 이상 좌표가 유효 항적·평균·추정 기준을 오염시키지 않게 한다. REQ-02.
- 입력: 식별자·전체 시각·연속 좌표.
- 기대 동작: POS-01~04를 적용하고 원본과 판정을 분리한다. 도약 후보 이후 두 연속 후보 조건으로 추적을 재개한다.
- 예외 상황: 시간 차 30분 초과는 도약 판단 유보, 같은 시각 다른 좌표는 충돌, 잘못된 시간은 시간 이상이다.
- 인수조건: 0.5해리와 60노트 조건을 모두 초과한 지정 관측만 도약 의심으로 분류하며 재개 시 이전 항적과 선을 잇지 않는다. 의심 원본은 보존된다.

### FR-004 시간에 따라 확대되는 부채꼴

- 설명: 회색 선박 선택 시 마지막 관측을 근거로 한 이동 범위 가정을 보여준다. REQ-04.
- 입력: 마지막 유효 위치·당시 SOG/COG·경과 시간.
- 기대 동작: FAN-01~04의 반경·각도·1분 갱신·2시간 기한을 적용하고 푸른 반투명 부채꼴·가정 문구를 표시한다.
- 예외 상황: 저속·미제공 속도/방향·잘못된 시각·2시간 초과는 사유와 함께 표시하지 않는다.
- 인수조건: 유효한 서로 다른 1분 갱신 시점의 반경이 증가하고 꼭짓점은 변하지 않는다. 새 유효 관측 시 종료하며 실제 위치·검증 확률로 표현하지 않는다.

### FR-005 선박 정보 팝업과 평균 속도

- 설명: 사용자 요청 항목을 근거 수준에 맞게 제공한다. REQ-05·10.
- 입력: 관측·선박 메타데이터·항만 연결·탐지 이력·최근 유효 SOG.
- 기대 동작: 선박 식별, 기국, 현재 위치 국가, 출발/도착 국가, 실제 적재 화물, 특이사항을 표시한다. AVG-01~02의 최근 관측 속도 평균·기간·표본 수도 표시한다.
- 예외 상황: 해역 경계·항구 연결·적재 자료가 없으면 해당 항목 데이터 부족. 이전/다음 항구를 최초 출발/최종 도착으로 바꾸지 않는다.
- 인수조건: 원자료에 없는 화물·국가를 생성하지 않는다. 평균은 최근 30분 안의 공백 조건을 충족한 서로 다른 3개 이상·10분 이상 구간의 유효 표본일 때만 표시된다.

### FR-006 기국 필터

- 설명: 등록국이 확인된 감시 선박을 골라 본다. REQ-06.
- 입력: 고정 감시 목록·확인된 등록국·기국 미확인 상태.
- 기대 동작: 전체/확인된 기국/미확인으로 목록과 지도를 함께 필터링한다.
- 예외 상황: 기국이 없으면 별도 미확인 항목에 남기며 현재 해역으로 대체하지 않는다.
- 인수조건: 필터 결과가 감시 집합의 부분집합이고 지도·목록의 수가 일치한다. 핀란드 화물 국가 선택과 혼동되지 않는다.

### FR-007 핀란드 해상 화물 자료

- 설명: 해상 운송만 최근 공개 24개월로 제공한다. REQ-07·09.
- 입력: 공식 12jd 월·품목군·방향·톤수와 출처 상태.
- 기대 동작: 국가 목록은 핀란드 하나, 상대국 전체 합계, 들어옴/나감 선택을 제공한다. POL-02·16에 따라 24개월 표시·비교용 직전 1개월·하루 1회 공표 확인.
- 예외 상황: 미발표·비공개·누락은 0과 다르게 표시하고 월 간격을 유지한다. 기존 자료가 없으면 데이터 부족.
- 인수조건: 전체 운송수단 관세 자료가 섞이지 않으며 최신 공개 기준월·출처·확인 시각이 보인다. 동일 기준월의 수정 공표도 이력과 함께 반영한다.

### FR-008 두 단계 품목 분류

- 설명: 서비스 상위 6분류를 누르면 원천의 16품목군까지만 펼친다. REQ-08.
- 입력: 공식 품목 코드·명칭과 아래 매핑.
- 기대 동작: 하위 품목의 중복 없는 합산으로 상위 값을 계산하고 원천 명칭도 확인할 수 있게 한다.
- 예외 상황: 알 수 없는 코드·분류 변경은 집계 불완전으로 표시하며 임의 생활용품에 넣지 않는다.
- 인수조건: 아래 16품목이 각각 한 번만 포함된다. 전체 합계 행과 개별 행을 중복 합산하지 않으며 세 번째 세분류가 없다.

| 서비스 상위 분류 | 공식 하위 품목군의 한국어 표시 |
|---|---|
| 목재·제지 | 원목, 제재목, 펄프, 종이, 합판·단판 |
| 연료 | 원유, 석유제품, 석탄·코크스 |
| 금속·광물 | 광석·정광, 금속·금속제품, 원료광물·시멘트 |
| 화학·비료 | 화학제품, 비료 |
| 곡물 | 곡물 |
| 일반·기타 화물 | 일반화물, 기타 상품 |

상위 6분류는 서비스 편의를 위한 묶음이며 공식 분류 계층이라고 주장하지 않는다. 생활용품·세제·식기는 현재 표의 분류가 아니다. 공식 코드·명칭을 보존하고 번역 명칭과 구별한다. [12jd 선택 표](https://statfin.stat.fi/PxWeb/pxweb/en/StatFin/StatFin__uvliik/12jd.px/)

### FR-009 물량·비중·전월 변화와 그래프

- 설명: 동일 집계 범위의 월별 변화를 설명한다. REQ-09·10.
- 입력: 같은 월·입출 방향·상대국 전체 범위의 품목 톤수 Q, 전체 톤수 T, 직전 달 Qprev.
- 기대 동작: 비중=100×Q/T, 전월 차이=Q−Qprev 톤, 증감률=100×(Q−Qprev)/Qprev. 선택한 품목/상위 분류의 월별 톤수 라인 그래프와 수치 표를 제공한다.
- 예외 상황: T=0이면 비중 계산 불가, Qprev=0이면 증감률 계산 불가(톤수 차이는 계산 가능). 누락·비공개가 필요한 합산에 있으면 불완전 표시하며 조용히 0으로 합산하지 않는다.
- 인수조건: 비중·증감률은 계산 후 소수점 1자리, 톤수는 원자료 정밀도를 유지한다. 하위 비중도 기본 분모는 같은 월 전체 톤수이며 분모를 표시한다. 누락 월은 선을 끊고 임의 보간하지 않는다.

### FR-010 수집 장애 탐지·진단

- 설명: F-01~03을 관측 품질 사건과 구별한다. REQ-11.
- 입력: 요청 결과·응답 시간·생존 상태·관측 신선도.
- 기대 동작: 요청별 5xx/10초 초과, 생존 3회 연속 실패를 사건으로 기록하고 Diagnosis가 증거와 원인 후보를 반환한다.
- 예외 상황: 단독 신호로 외부 제공자 전체 장애를 확정하지 않는다. 신규 통계 미발표·개별 선박 공백은 수집 오류가 아니다.
- 인수조건: 세 모의 장애가 구분되며 감시가 계속 작동한다. 동일 수집원의 열린 사건에 반복 증거가 합쳐진다.

### FR-011 제한된 복구 실행

- 설명: 허용 범위 안의 조치만 실행한다. REQ-11·13.
- 입력: 진단·정책·잔여 한도·허용 대상.
- 기대 동작: 추가 요청 3회/5·15·30초 대기·허용 수집기 재시작 1회·활성 180초를 적용한다.
- 예외 상황: 요청 제한·불명 원인·남은 기한 부족은 안전 중단한다. 재시작 실패를 반복 재시작으로 해결하지 않는다.
- 인수조건: 모든 조치에 사건·시도 ID와 전후 결과가 있고 횟수·시간 상한 밖의 조치가 0건이다.

### FR-012 회로 차단·인계·재개

- 설명: 실패가 자동 루프로 이어지지 않게 한다. REQ-13.
- 입력: 실패·상한·기한, 냉각 시각, 운영자 확인.
- 기대 동작: §10의 상태 전이와 POL-07·11을 적용한다. 300초 뒤 읽기 1회 이후에도 운영자 확인과 새 검증 전에는 차단을 유지한다.
- 예외 상황: 확인 실패·운영자 미확인·프로그램 재시작은 같은 사건·한도·중단 상태를 유지한다.
- 인수조건: 냉각 검증 성공만으로 정규 수집이 재개되지 않는다. 운영자 요청 후 독립 검증에 성공한 경우에만 사건을 닫는다.

### FR-013 복구 결과 독립 검증

- 설명: 실제 데이터 정상화 근거가 있는 사건만 성공으로 종료한다. REQ-12.
- 입력: 사건 전 관측 기준·새 원천 자료·생존·저장/표시 상태.
- 기대 동작: POL-08·09로 자료 유형을 구별해 최대 30초 내 성공/실패/판단 불가를 반환한다.
- 예외 상황: HTTP 성공·재시작 응답·캐시·미래 시각·추정 부채꼴만 있으면 성공 불가.
- 인수조건: AIS는 새 유효 관측 1건 이상과 0~10분 나이를 확인하고 다른 미수신 선박은 남겨 둔다. 통계는 기존 공개 월의 정상 응답으로 검증할 수 있다.

### FR-014 누적 이력과 출처

- 설명: 관측·판정·사건·통계를 추적 가능하게 보존한다. REQ-10·14.
- 입력: 원본·관측 시각·판정·시도·확인·통계 버전.
- 기대 동작: §15의 필수 기록과 30일/24+1개월 보존을 적용한다. 사건 한도와 감시 목록은 재시작 후에도 유지한다.
- 예외 상황: 기록 실패 시 정상 완료를 선언하지 않으며 열린 사건 근거는 만료 정리에서 제외한다.
- 인수조건: 동일 관측 중복이 없고 원본에서 표시·판정·복구 결과까지 추적할 수 있다. 원본 좌표를 추정값으로 덮어쓰지 않는다.

### FR-015 운영자 사건 확인

- 설명: 사람에게 필요한 판단을 전달한다. REQ-13·14.
- 입력: 차단/불명/검증 결과, 담당자의 확인.
- 기대 동작: 로컬 운영 경로에 사건·근거·시도·필요 조치·전달/확인 상태를 지속 표시하고 재개 요청을 기록한다.
- 예외 상황: 전달 실패는 미전달로 남기며 일반 조회 화면에서는 재개할 수 없다.
- 인수조건: 운영자 확인과 독립 검증이 별도 기록이며 임의 명령·자동 승인·외부 메시지 기능이 없다.

### FR-016 공통 화면 상태와 접근

- 설명: 자료의 부족·지연·오류·복구를 사용자가 구별한다. REQ-05·09·10·15.
- 입력: 자료 상태·사용자 선택·오류·모드.
- 기대 동작: §7의 로딩·빈 상태·부분 부족·지도 실패·재생 모드를 표시한다. 키보드로 필터·팝업·분류·수치 표를 이용할 수 있게 한다.
- 예외 상황: 지도나 외부 요청이 실패해도 보유한 목록·시각·상태를 유지한다.
- 인수조건: 색 없이 상태를 읽을 수 있고 팝업 종료 후 초점이 복원된다. 실시간/재생, 관측/계산/추정, 통계 기준월을 혼동시키는 표기가 없다.

## 15. 데이터와 로그 요구사항

상세 DB·파일 형식은 후속 기술 설계에서 정한다. 이 절은 저장해야 하는 의미·관계·보존 조건을 정의한다.

| 기록 단위 | 필수 내용·관계 | 일관성 조건 |
|---|---|---|
| 감시 선박 | 식별번호·선박명·기국 근거·감시 선정 시각·목록 상태 | 최대 100척, 미확인 속성은 결측, 목록 영속 보존 |
| 원본 관측 | 선박 ID·원천·전체 관측 시각·수집 시각·좌표·SOG/COG·원천 미제공 표식 | 원본 불변, 동일 선박/원천/관측 시각 중복 식별, 같은 시각 다른 위치는 충돌 보존 |
| 관측 판정 | 원본 참조·시간/위치 유효성·공백/도약·근거·정책 버전 | 최신 신규 원본 시각과 마지막 유효 위치 시각 구분, 오류 시각은 판정 기준에서 제외 |

관측·판정·종료 사건은 30일, 통계는 표시 24개월+전월 비교용 1개월을 보존한다. 하루 1회 앱 전용 저장 범위에서 만료 기록을 정리한다. 열린 사건의 근거·시도와 마지막 유효 관측은 사건 종료까지 보존한다. 종료 후 만료 정책을 적용하되 참조를 끊은 채 불완전한 성공 이력을 남기지 않는다. 자동 외부 백업·무기한 저장은 제외한다.

시각은 UTC로 기록하고 화면 기본 표시는 Asia/Seoul로 한다. 통계 기준월은 원자료의 월 정의를 유지한다. 원천 관측·수집·공표·수정 시각을 혼합하지 않는다. 모의/재생 자료에는 별도 모드와 논리 시계를 붙이며 실시간 이력에 합산하지 않는다. 비밀키·토큰·비밀번호와 불필요한 개인정보는 로그에서 제외한다.

### 시간과 성과의 정의

- 발생 시각: 알려진 모의 장애의 시작. 실제 외부 장애 시작을 모르면 미확인.
- 탐지 시각: Monitor가 사건을 생성한 시각.
- 활성 시작: Orchestrator가 해당 사건의 Diagnosis를 처음 호출한 시각.
- 첫 조치 시각: Recovery가 실제 첫 허용 행동을 시작한 시각.
- 정상 확인 시각: Verification이 유효 자료와 정상 기능을 독립 확인한 시각.
- 탐지 소요시간 = 탐지−발생; 여러 사건 평균은 MTTD.
- 전체 정상화 소요시간 = 정상 확인−발생; 알려진 발생 시각을 가진 정상화 사건의 평균은 MTTR.
- 활성 복구 시간 = 정상 확인−활성 시작. **180초 목표는 이 값**이며 발생부터 180초라는 뜻이 아니다.
- 차단 이후 냉각·읽기 확인·운영자 대기는 인계 구간으로 별도 기록. 사람 확인 후 정상화는 자동복구 성공에서 제외하고 전체 경과시간을 함께 보고한다.
- 자동복구 성공률은 사전에 정의한 복구 가능 9회 중 기한 안에 독립 정상화한 횟수/9다. 실패·미완료를 분모에서 빼거나 안전 중단을 성공으로 넣지 않는다.

5분 정규 조회 직후 생긴 요청 장애는 다음 조회까지 탐지가 늦어질 수 있다. 따라서 실제 발생부터의 MTTR은 활성 예산보다 길 수 있다. 발생 시각 미확인·재생 논리 시계·실시간 시계의 결과는 분리한다.

PRD 문서 완료 조건은 필수 20절·요구사항·근거·상태가 갖춰지고 독립 검수가 통과한 뒤 사용자가 최종 승인하는 것이다. 제품 완료는 별도로 위 인수조건의 실제 결과가 확인돼야 한다. 문서 검수 통과를 제품 동작 검증으로 대체하지 않는다.

검수 대상으로 제출할 묶음은 워크시트 v0.4와 PRD v0.1이다. 제출 전 원문을 세션에 보존하고 검수자는 실제 저장 파일의 SHA-256·규칙별 판정·근거를 회신한다. 통과 뒤 그 원문·해시·배정표·결과를 체크포인트로 보존한다. 이 절은 통과를 미리 선언하지 않는다. 결과 기록만을 위해 통과 파일을 다시 수정하지 않고, 결과는 독립 검수 응답과 세션 기록에 연결한다.

검수 실패 시 작성자는 제출 원문 또는 직전 유효 통과 체크포인트에서 필요한 부분만 수정한다. 변경 영향을 받는 가장 이른 규칙부터 같은 담당이 재검수하며 이전 버전 판정을 새 버전에 재사용하지 않는다. 추가 검수 단계가 생기면 앞 단계 통과 후에만 실행한다.
