## 2. 프로젝트 개요

**Auto Healing이 프로젝트의 주목적**이다. 선박 해상 화물 모니터는 지원 가능한 공개·비상업 데이터로 선박 관측과 국가별 해상 수출입 카테고리를 조회하는 웹앱이다. 수집 장애의 탐지→진단→제한 복구→독립 검증→차단/사람 인계가 핵심이며 지도·통계·읽기 전용 조회 AI는 이를 적용·검증하는 업무 서비스다. 정상 기준선·복구 통제·필수 기록은 P0이며 초기 Healing 시연과 전체 제품 완료를 구별한다.

제품은 브라우저에서 사용하는 교육용 웹앱이다. 최초 사용 범위는 로컬 Windows 11 PC 한 대와 최신 안정 Chrome·Edge다. 공개 API 이용과 로컬 영속 저장을 기본으로 하고, 공개 배포·클라우드·다중 사용자 계정은 이번 MVP에서 제외한다. 일반 사용자·기업·개인사업자를 장래 사용자로 삼되 실습에서는 팀이 그 사용 흐름을 시연한다.

Auto Healing 대상 업무 에이전트는 **6번 선박 신호 공백·이상 탐지**를 유지한다. 제품에는 통계 조회·집계와 새 읽기 전용 사용자 조회 AI를 포함한다. 자동 복구 역할은 결정적 워크플로로 설계하며 각각 별도 LLM을 요구하지 않는다. 조회 AI의 모델 실행은 별도 미검증 사항이다.

## 3. 문제 정의

지도에 남은 마지막 좌표만으로는 선박이 현재도 그 위치에 있는지, 새 신호가 없는지, 수집기가 멈췄는지 알기 어렵다. 위치가 비정상적으로 튀는 관측까지 정상 항적으로 처리하면 평균 속도와 항적이 왜곡된다. 사용자는 관측 사실·계산값·품질 판정을 구별해야 한다.

각 국가의 해상 수출입 상품 규모·비중·증감에는 실제 Sea 범위·분류판·주기·단위·누락 상태가 필요하다. 이 통계는 개별 선박의 현재 적재 품목을 알려주지 않는다. 서로 다른 자료를 하나의 화물 추적 결과처럼 합치지 않는 것이 핵심이다.

수집 요청 오류나 자체 수집기 중단이 발생하면 운영자는 실패 원인과 조치 이력을 확인하고 재조회·재시작 뒤 실제 자료가 정상화됐는지 확인해야 한다. 현재 사용자의 실무 대응 경험과 수동 소요시간은 제공되지 않았으므로 절감률을 만들어 쓰지 않는다. 교육 실습의 영향은 자료 지연과 분석 중단 수준의 중간 심각도이며, 항해 안전·실제 물류 의사결정 보장을 목표로 하지 않는다.

일반 조회 화면에는 재개·정책 변경 권한을 부여하지 않는다. MVP는 로컬 실행 계정의 실습 담당자만 운영 기능에 접근하는 환경을 전제로 한다. 불특정 사용자가 접속하는 서비스의 인증·권한 체계를 구현했다고 간주하지 않으며, 외부 공개 시에는 별도 권한 설계가 필요하다.

## 7. 정상 서비스 시나리오

### 화면 구조와 공통 상태

상단에는 **선박 모니터링 / 해상 화물 통계** 두 진입점을 유지한다. 선박 화면은 지도·목록·기국 필터·상세 카드·기간별 항적, 화물 화면은 국가 사이드 선택·자료 모드·방향·기간·분류·그래프/수치 표다. 읽기 전용 질문 패널은 두 화면의 명시한 조건을 참조한다. 운영 사건 화면은 담당자만 사용하는 별도 경로이며 질문 패널과 권한을 공유하지 않는다.

정상 선박은 유효 진행 방향의 색 있는 화살표, 미수신은 회색·마지막 유효 위치·경과 시간과 상태 문구로 표현한다. 방향이 없으면 방향 없는 표식을 사용한다. 색만으로 의미를 전달하지 않고 목록·텍스트로 같은 내용을 확인하게 한다. 팝업·필터·품목 펼치기는 키보드로 조작하고 팝업 닫기 후 선택 항목으로 초점을 돌린다.

| 공통 상태 | 화면 동작 |
|---|---|
| 최초 로딩 | 불러오는 자료와 진행 상태 표시; 이전 자료가 없으면 빈 틀을 정상 값처럼 채우지 않음 |
| 조회 결과 없음 | 실제 확보 수 0·자료 없음과 마지막 시도 시각 표시 |
| 일부 필드 부족 | 항목별 데이터 부족과 사유; 다른 유효 필드는 유지 |
| 갱신 실패·캐시 존재 | 마지막 성공 자료·관측/기준 시각·지연 또는 복구 상태 함께 표시 |
| 지도 실패 | 선박 목록·시각·상태·팝업 정보 유지, 지도 재시도 안내 |
| 재생 모드 | 모의/재생 배지·논리적 기준 시각 표시; 실시간 자료와 섞지 않음 |

### S-01 선박과 관측 공백 탐색

활성 수집 범위에서 유효 신규 선박이 발견되면 감시 집합에 추가한다. 단순 미수신·필터 변경으로 기존 선박을 교체하거나 삭제하지 않는다. 집합 버전·변경 시각·이유를 영속 보존하고 명시적 범위 변경에 따른 비활성화에도 항적·열린 사건은 보존한다. 지도와 목록은 같은 조건·기준 시각·집합 버전을 사용하며 전체 일치 수와 페이지/영역별 표시 수를 구별한다. 페이지·지도 영역·표시 축약은 응답/렌더링 장치이며 저장 선박 수 상한을 대신하지 않는다.

공급자별 원본은 보존한다. 같은 MMSI의 동일 관측을 여러 공급자가 전달해도 최신성·평균·관측 횟수를 부풀리지 않는다. 대표 위치는 최신 유효 전체 레코드에서 선택하며 서로 다른 출처·시각의 위치/SOG/COG를 합성하지 않는다. 동시각 위치 충돌은 보존·표시하고 임의 정상화하지 않는다. 과거·미래·단위 오류 자료는 최신 유효 위치를 덮어쓰지 않는다.

제품의 REST 정규 조회는 5분, 스트림은 공급자 방식의 지속 수신이며 제품 상태 점검 주기와 구별한다. 정상 WebSocket 연결 수명에 10초 요청 제한을 적용하지 않는다. 개별 메시지 부재만으로 연결·프로세스 장애를 판정하지 않고 공급자별 건강 신호 계약을 확인한다. Digitraffic의 시각 단위·흘수·미제공 값 해석을 다른 공급자에 일괄 적용하지 않는다.

마지막 신규 원본 시각과 마지막 유효 위치 시각을 구별한다. 미수신 선박 선택 시 카드·공백 상태를 보여주고 유효 재관측 후 정상 표시로 돌아가며 공백 사건을 보존한다. 위치 도약 후에는 POS-03의 두 후보 조건을 거쳐 추적을 재개한다.

### S-02 선박 상세 확인

선박 클릭 카드에는 이름·MMSI·IMO, 확인된 기국, 원천 선종, 마지막 위치·신선도, SOG/COG, AVG-01~02의 최근 관측 속도 평균(구간·표본 수), 흘수, 목적지 원문, 항만/시간, 원천 항해 상태와 품질·공백 상태를 제공한다. 현재 위치 국가·출발/도착 국가·실제 적재 화물은 각각 별도 근거가 있을 때만 표시한다. 국가 통계나 선종을 실제 적재 화물로 바꾸지 않는다.

항만 방문·항해 연결에는 출처·방문 식별자·항만·시각 종류를 보존한다. **ATD=실제 출항, ATA=실제 입항, ETA=예상 입항, ETD=예상 출항**을 구별하고 정확히 같은 항해의 출발/도착 방문임을 확인한 경우에만 “출발 → 도착”으로 연결한다. 이전/다음 항구를 최초 출발/최종 도착으로 승격하지 않는다. AIS reported ETA는 연도 없는 MMDDHHMM UTC 값이라는 한계를 표시하고 임의 연도를 붙여 지연을 계산하지 않는다. 완전한 시각을 가진 항만 방문 ETA와도 구별한다.

Digitraffic의 이름·MMSI·IMO·shipType, 위치 sog/cog/navStat/timestampExternal 및 조건부 항만 방문 자료를 후보로 삼는다. shipType은 cargo 70/tanker 80처럼 축약될 수 있어 Bulk Carrier 등 상세 선종을 보장하지 않는다. draught는 0.1m 단위로 변환하고 0은 미제공으로 처리한다. 항목별 원천 갱신 시각·수집 시각과 부족 사유(미제공/연결 불가/자료 오래됨 등)를 구분한다. 사진은 재사용 권한이 확인된 경우에만 제공하고 기본은 자리표시자다. 사용자 첨부 3장은 UI 참고이며 복제·재사용 권한이 아니다.

### S-03 국가별 해상 화물 탐색

분석 대상 국가 선택에는 고정 국가 상한을 두지 않으며 실제 지원은 원천·조합별 확인 결과로 표시한다. 보고국·상대국·선박 기국·수신 해역은 서로 다르다. 기존 Eurostat 조사 25개 보고국은 BE 벨기에, BG 불가리아, DK 덴마크, DE 독일, EE 에스토니아, IE 아일랜드, EL 그리스, ES 스페인, FR 프랑스, HR 크로아티아, IT 이탈리아, CY 키프로스, LV 라트비아, LT 리투아니아, MT 몰타, NL 네덜란드, PL 폴란드, PT 포르투갈, RO 루마니아, SI 슬로베니아, FI 핀란드, SE 스웨덴, NO 노르웨이, ME 몬테네그로, TR 튀르키예다. 이는 과거 확인 범위이며 제품의 국가 목록 제한이 아니다. EL 등 원천 코드는 보존한다.

- **국가별 해상 수출입 상품 모드:** UN Comtrade 등 후보에서 실제 Sea가 확인된 국가×기간×품목 조합만 제공한다. 위임 초기안은 HS 2자리→HS 4자리 한 단계 펼침이며 HS 6자리 추가 드릴다운은 포함하지 않는다. 분류체계·개정판·코드·레벨·부모를 보존한다. 기본 상대국은 전체 합계 초기안이며 복잡한 양자 무역 UI를 추가하지 않는다.
- **핀란드 월별 품목 모드:** Statistics Finland 12jd, 서비스 6분류·공식 16품목, Import/Export, 톤, 최신 공개 24개월+직전 비교 1개월. Country 차원은 상대국이므로 분석 핀란드에는 Country=Total을 사용한다.
- **분기 화물형태 모드:** Eurostat mar_go_qmc, THS_T(천 톤), TOTAL 및 가용 LBK 액체 벌크·DBK 건조 벌크·LCNT 대형 컨테이너·RO_TOT 로로·OTH 기타. IN/OUT은 하역/적재이며 수입/수출 상품으로 개명하지 않는다. 최신 공개 8개 달력 분기+직전 비교 1분기 확보 목표다. 연간 NST 20품목은 이번 범위에 추가하지 않는다.

HS·12jd 6/16품목·Eurostat 화물형태 사이 임의 매핑은 금지한다. 확인된 원천 상품 코드는 제공할 수 있으나 일반화물을 생활용품으로 바꾸는 근거 없는 세분화는 하지 않는다. AIS shipType cargo 70은 선종이며 적재 상품 품목이 아니다. 국가 통계를 개별 선박 적재 명세로 연결하지 않는다.

월 자료는 24+1개월, 분기 자료는 8+1분기이며 연자료만 확인되면 명시적인 연간 모드로 제공한다(초기안: 최근 공개 2년+직전 비교 1년). 연간값을 월값으로 생성하지 않는다. 중량 중심으로 확인된 중량 필드·단위만 톤으로 변환하고 원값·원단위·변환 근거를 보존한다. 금액·수량으로 중량을 대신하거나 금액·TEU 분석을 신규 필수 기능으로 넣지 않는다. 천 톤은 ×1,000, kg이면 ÷1,000이며 필드 단위가 확인된 경우에만 변환한다.

국가×원천×운송모드×분류판/레벨×주기×방향×분류×기간×상대국 범위의 가용성을 판정한다. **미지원, 미발표, 해당 기간 자료 없음, 비공개/결측, 일시 조회 실패**를 0과 구별하며 자격·Sea 확인 전은 별도의 **미확인**이다. 국가 변경 시 선택 식별자로 늦은 이전 응답을 격리한다. 이전 자료를 남기면 이전 국가 이름과 새 요청 상태를 함께 표시한다. 호환되지 않는 방향·분류는 해당 조합의 가용 전체값·최신 공개 기간으로 바꾼 이유를 알리고, 없으면 선택 해제·자료 부족을 표시한다.

국가 간 비교는 같은 원천·정의·운송모드·분류판·주기·단위·방향·상대국 범위·공통 기간만 사용한다. 서로 다른 분류판을 자동 비교하지 않는다. 비중 분모는 같은 조건의 원천 전체값이며 현재 페이지 품목 합계를 전체 분모로 쓰지 않는다. 상위 합계와 하위를 중복 합산하지 않고 필수 하위가 누락/비공개면 합계 불완전을 표시한다. TOTAL=IN+OUT을 가정하지 않는다. 직전 기간은 달력상 직전 월/분기/연도이며 결측을 건너뛰어 비교하지 않는다. 월·분기·연도를 이어붙이거나 누락을 보간하지 않는다. Eurostat의 분기 공표 지연(최대 10개월)과 국가별 포함 항만 차이도 알린다.

**Sea 확인 게이트:** 선행 조사에서 익명 Comtrade preview에 motCode=2100을 요청했지만 HTTP 200 응답 행의 motCode=0(전체 운송수단)이 확인됐다. 그러므로 요청 매개변수나 HTTP 성공만으로 해상 필터 성공을 주장하지 않는다. 정확한 실서비스 API·접근 자격에서 실제 Sea 행·상품 레벨·중량 단위를 확인해야 한다. Sea가 없으면 WATER/All Modes/미지정으로 대체하지 않고 미확인 또는 미지원으로 남긴다. 미지원 응답 처리를 구현하는 것과 해외 Sea 상품 확보는 별개이며 자료 미확보를 지원 완료로 표시하지 않는다.

공식 문서 조사 조건(2026-10-29): [API](https://uncomtrade.org/docs/un-comtrade-api/), [preview 최대 500레코드](https://uncomtrade.org/docs/what-is-data-preview/), [구독·무료 개인 API 하루 500호출/호출당 최대 100,000레코드](https://uncomtrade.org/docs/subscriptions/), [가용성](https://uncomtrade.org/docs/data-availability/), [운송모드](https://uncomtrade.org/docs/mode-of-transport-and-trade-routes/), [HS 계층의 포함 관계](https://uncomtrade.org/docs/are-6-digit-commodity-codes-included-in-4-digit-commodity-codes-or-are-they-separate/). [옛 이용 계약](https://comtrade.un.org/licenseagreement.html)은 현서비스 권한의 법적 확정 근거로 쓰지 않으며 실제 무료 접근·저장·표시/재배포 조건 확인이 남아 있다. [테스트 도메인 운송모드 참조](https://comtradeplus-test.azurewebsites.net/en/reference-tables?table=mot)는 최종 실서비스 검증과 구별한다. 이번 선행 조사는 익명 2회이며 무료 키 Sea 실데이터는 미확인이다. 문서 작성자는 API 실험을 재현하지 않았다.

### S-04 정상 수집·저장

수집 자료는 원본과 계산·판정을 구분해 저장한다. 동일 관측 재조회는 중복 누적이나 시각 갱신으로 처리하지 않는다. 관측 2년·운영 종료 로그 30일은 §15의 독립 정책을 따른다. 통계 새 공표 확인은 하루 1회이며 미발표는 장애가 아니다. 마지막 정상 자료 표시만으로 복구 성공을 선언하지 않는다.

### S-05 항적 확인

선박 카드의 **항적 보기**에서 기본 24시간, 7일·30일·1년·2년·사용자 지정 기간을 선택한다(기간 프리셋과 기본값은 위임 초기안). 요청 기간과 실제 확보 기간을 함께 표시하고, 보존 전/수집 전·자료 없는 기간을 정상 항적으로 채우지 않는다. 지도에는 관측점과 관측 연결선을 구별하며 연결선은 두 관측 사이 실제 이동경로의 증명이 아니다.

신규 원본 관측 간격이 15분 이상인 공백은 재수신 후 양쪽 유효 위치가 있을 때 **주황색 점선**과 “미관측 구간 연결 — 실제 경로 아님”으로 표시한다. 재수신 전에는 마지막 유효 점과 열린 시간 구간만 표시하고 가짜 종점·추정 항적을 만들지 않는다. 위치 도약·동시각 충돌·시각 오류는 **붉은 이상 표식과 항적 단절**이며 공백 점선으로 변환하지 않는다. POS-03 추적 재개 때 이전 위치와 선을 잇지 않는다. POS-02의 30분 초과 도약 판정 유보와 15분 공백 시각화는 별개다. 이상이 끼어 있는 구간은 시간 공백이 겹쳐도 붉은 단절을 유지한다. 미수신 선박의 회색·마지막 유효 위치·경과 시간은 유지한다.

색·선형·범례·상태 문구와 구간 표(시작/끝·열림 여부·유형·근거)를 함께 제공한다. 장기 조회 축약은 조회 응답과 렌더링에만 적용한다. 원본을 삭제·덮어쓰지 않고 공백/이상 경계를 넘어 축약하지 않으며 각 구간의 양끝점을 보존한다. 원본 수·표시 수·축약 여부를 밝히고 과대 조회에는 구간별 페이지 또는 기간 축소 안내를 제공한다.

### S-06 보유 자료 질문

조회 AI는 우리 서비스가 실제 보유한 자료를 자연어로 조회하는 별도 읽기 전용 기능이다. 자연어 → 제한된 조회 조건 → 가용성 확인 → 허용 읽기 도구/결정적 계산 → 근거 응답 순서를 따른다. 화면 선택을 사용하면 답 첫 줄에 적용 국가·원천·운송모드·분류판/레벨·주기·방향·분류·기간을 명시한다. 방향이 없고 선택에 따라 답이 달라지면 먼저 묻는다. “핀란드에서 최근 증가한 물류/추세?”에는 원천과 분류를 식별하고 해상 수출입 상품(월/연)·핀란드 월 품목·분기 화물형태 중 어느 모드인지 확인하거나 적용 화면 조건을 명시한다.

초기 해석은 최근=해당 조합의 최신 공표 기간, 증가=확인된 중량 기준 직전 달/분기/연도 대비 톤수 변화, 추세=최근 6개 연속 달력 기간의 첫 값과 끝 값의 변화다. 가용한 연속 기간이 3~5개면 실제 기간 수와 제한을 명시하고, 3개 미만 또는 선택 구간 중간 결측이면 추세 판단 불가로 응답한다. 끝점 변화는 매 기간 단조 증가·계절조정 추세·예측을 뜻하지 않는다. 원인 추측·운항 추천은 하지 않는다.

수치·순위·차이·비율은 결정적 계산 도구 결과만 인용한다. 모델이 직접 계산하거나 없는 셀을 만들지 않는다. 답에는 국가·원천 표·운송모드·분류판/레벨·분류·방향·기준/비교 기간·단위·계산 분모·조회 시각·잠정/누락/공표 지연·관련 화면 링크와 사용 셀/계산 근거를 포함한다. 확인 가능한 근거가 없으면 답변 불가와 필요한 조건을 제시한다.

무료 또는 로컬 모델은 아직 선정·실행 검증하지 않았다. 후보의 이용 조건·한국어 질의 변환·근거 준수·장비 성능을 구현 전에 확인해야 한다. 유료 키나 외부 전송은 임의 허용하지 않는다. 모델 오류·가용성 부족 시 정형 조회와 근거 표로 대체하되 이것만 동작하면 “AI 완료”로 처리하지 않는다. 모델 장애는 AIS 수집기 재시작의 근거가 아니다.

모든 재현 방법은 **후속 구현 단계의 격리 실습 설계**다. 실제 제공자 API에 오류를 유발하지 않으며 이번 문서 개정에서는 프로세스를 중단하지 않는다.

## 9. 멀티 에이전트 구성

Auto Healing 대상 업무는 6번 신호 공백·이상 탐지이며, 아래 복구 역할과 새 조회 AI는 책임·권한을 분리한다. 하나의 프로그램 안에서 규칙 기반 기능으로 구현할 수 있다. 실제 프로세스 분리 여부는 후속 기술 결정이지만 자체 수집기가 중단돼도 감시·판정이 작동해야 한다.

### 공급자별 사건과 독립 정상화 계약

Monitor·Diagnosis·Recovery·Verification·Orchestrator·Notification의 6역할은 provider/수집 스트림·설정 범위를 사건·요청·연결·검증 근거에 보존한다. 공급자 A 장애는 A의 사건 기준 이후 새 유효 관측으로 독립 확인하며, 공급자 B에서 같은 선박의 새 관측을 받았다는 이유로 A 사건을 종료하지 않는다. AIS 정상화의 관측 나이 0~10분·독립 검증 30초·활성 180초 조건을 유지하고 근거가 없으면 판단 불가로 남긴다.

계정 단위 쿼터·429 대기 지시를 준수하며 사건·영역·키·연결을 나눠 예산을 증폭하지 않는다. 독립 검증용 추가 연결도 같은 공급자 상한을 따른다. 인증·자격·권한 철회·쿼터 제한은 무조건 재시작하는 사유가 아니며 대기/중단/인계한다. 공급자 대기가 활성 기한을 넘으면 안전 중단한다. 개별 미수신·커버리지 부재·제공자 제외 선박·미공표·모델 실패도 수집 고장으로 승격하지 않는다.

통계 정상화는 같은 원천·보고국·상대국 범위·운송모드·분류판·주기/기간·방향·단위의 이미 공개된 자료로 독립 확인한다. HTTP 200만으로 해상 필터나 자료 정상화를 인정하지 않는다. 추가 요청 최대 3회(5·15·30초 대기), 허용 수집기 재시작 1회, 180초 기한, 차단 후 300초 냉각과 읽기 1회, 운영자 확인+새 독립 검증, 영속 한도와 금지 행동은 그대로 유지한다. 재생/실시간, 자동 정상화/안전 중단/사람 개입 결과를 분리한다.

활성 수집원별 정상 기준선을 확보하면 독립적으로 가능한 Auto Healing 준비를 진행할 수 있으며 미지원 후보 전체 연동이나 조회 AI 완료를 선행시키지 않는다. 초기 Healing 시연은 전체 제품 완료와 다르며 미확보 상품·후보 연동·미완료 필수 기능을 완료로 세지 않는다.

### Monitor

- 책임: 수집 오류·생존·관측 시각·위치 이상 신호를 관찰하고 사건 후보 생성.
- 입력: 응답 코드·지연, 생존 상태, 신규 관측·통계 공표 상태.
- 출력: 사건 ID·추적 ID·공급자/스트림/설정 범위·유형 후보·대상·탐지 시각·증거.
- 사용할 수 있는 정보: 원천 응답, 최근 관측, 허용된 생존 상태.
- 허용 행동: 읽기·사건 기록; REST5분/스트림 지속 수신 구별과 10초 생존 점검. 원천별 건강 신호 계약 적용.
- 금지 행동: 재시작·설정 변경·복구 성공 선언.
- 실패 시 행동: 감시 불가를 표시·기록하고 정상 상태로 가장하지 않음.

### Diagnosis

- 책임: 요청 실패·자체 중단·관측 품질 사건·원인 불명을 근거에 따라 구분.
- 입력: Monitor 사건, 상태·응답·관측 이력.
- 출력: 분류·근거·불확실성·허용 전략 또는 사람 인계.
- 사용할 수 있는 정보: 해당 사건 증거와 승인 정책.
- 허용 행동: 읽기·분류·근거 기록.
- 금지 행동: 직접 복구·허용목록 수정·신호 공백 원인의 단정.
- 실패 시 행동: 5초 내 판정하지 못하거나 증거가 충돌하면 판단 불가로 중단·인계.

### Recovery

- 책임: Orchestrator가 승인 정책 안에서 선택한 복구 조치 수행.
- 입력: 사건 ID, 허용 전략·대상, 잔여 횟수·시간.
- 출력: 시도 ID·시작/끝 시각·조치 결과·오류.
- 사용할 수 있는 정보: 허용된 수집원·수집기·사건 한도.
- 허용 행동: 제한 재조회/재연결·허용 수집기 재시작.
- 금지 행동: 사건 성공 판정, 임의 명령·다른 프로세스 제어·원본 수정.
- 실패 시 행동: 실패 결과만 보고; 스스로 재귀 호출하지 않음. 요청은 10초, 재시작 상태 확인은 30초 상한.

### Verification

- 책임: 복구 실행 결과를 별도의 읽기 관측으로 검증.
- 입력: 사건 기준 관측, 시도 결과, 독립 확인 자료.
- 출력: 성공/실패/판단 불가·근거·확인 시각.
- 사용할 수 있는 정보: 원천의 새 관측·정상 통계, 자체 생존·저장·표시 상태.
- 허용 행동: 독립 읽기와 검증 기록.
- 금지 행동: 복구 조치·정책 변경, Recovery의 자기보고나 캐시만으로 성공 선언.
- 실패 시 행동: 30초 내 근거 확보가 안 되면 판단 불가; 중단·인계하며 성공으로 기록하지 않음.

### Orchestrator

- 책임: 중복 사건 병합, 순서·상태·횟수·시간·차단·재개 통제.
- 입력: 사건과 각 역할 결과, 운영자 확인.
- 출력: 역할 호출·상태 전이·종료/차단·전달 요청.
- 사용할 수 있는 정보: 열린 사건·영속 한도·승인 정책·독립 판정.
- 허용 행동: 진단→조치→검증 호출, 한도 관리, 검증 결과에 따른 종료.
- 금지 행동: 직접 복구 도구 조작, 한도 초기화 우회, 검증 없는 성공 선언.
- 실패 시 행동: 180초 활성 기한 도달 또는 상태 불일치 시 조치 중단. 재시작 후에도 이전 사건·횟수를 이어받음.

### Notification

- 책임: 로컬 운영 사건 화면에 필요한 인계와 결과를 지속 표시.
- 입력: 사건 상태·근거·시도·검증 결과·운영자 확인 필요 여부.
- 출력: 전달/확인 상태와 기록.
- 사용할 수 있는 정보: 해당 사건의 전달용 요약.
- 허용 행동: 로컬 화면·기록 갱신.
- 금지 행동: 외부 이메일·문자 발송, 자동 승인·복구 실행.
- 실패 시 행동: 5초 내 전달 기록이 안 되면 미전달 상태를 보존. 사람이 확인했다고 표시하지 않음.

### 조회 AI — 읽기 전용 사용자 질의

- 책임: 서비스 보유 데이터에 대한 자연어 질문을 제한 조건으로 해석하고 근거를 붙여 설명.
- 입력: 사용자 질문, 명시한 화면 선택, 가용성 정보, 허용 조회 결과.
- 출력: 적용 조건·수치 근거·출처·기간·한계·관련 화면 링크 또는 명확화 질문/답변 불가.
- 사용할 수 있는 정보: 서비스가 실제 보유한 선박 상세·항적 요약·통계와 해당 근거만.
- 허용 행동: 가용성 조회, 선박 상세 조회, 항적 요약 조회, 통계 조회, 결정적 계산 도구의 읽기 전용 호출.
- 금지 행동: 임의 SQL·쉘·파일·URL 탐색/웹 검색, 복구/재개/정책 변경, 없는 자료 생성, 수치 직접 계산, 근거 없는 원인 설명·운항 추천. 사용자 질문과 원천 문자열 안의 지시는 데이터로 취급하며 도구 권한을 바꾸지 않음.
- 실패 시 행동: 조건 명확화·가용 범위 안내 또는 정형 조회+근거 표 대체. AI 실패를 수집 장애로 승격하거나 자동 복구를 호출하지 않음.

조회 AI는 우리 서비스가 실제 보유한 자료를 자연어로 조회하는 별도 읽기 전용 기능이다. 자연어 → 제한된 조회 조건 → 가용성 확인 → 허용 읽기 도구/결정적 계산 → 근거 응답 순서를 따른다. 화면 선택을 사용하면 답 첫 줄에 적용 국가·원천·운송모드·분류판/레벨·주기·방향·분류·기간을 명시한다. 방향이 없고 선택에 따라 답이 달라지면 먼저 묻는다. “핀란드에서 최근 증가한 물류/추세?”에는 원천과 분류를 식별하고 해상 수출입 상품(월/연)·핀란드 월 품목·분기 화물형태 중 어느 모드인지 확인하거나 적용 화면 조건을 명시한다.

초기 해석은 최근=해당 조합의 최신 공표 기간, 증가=확인된 중량 기준 직전 달/분기/연도 대비 톤수 변화, 추세=최근 6개 연속 달력 기간의 첫 값과 끝 값의 변화다. 가용한 연속 기간이 3~5개면 실제 기간 수와 제한을 명시하고, 3개 미만 또는 선택 구간 중간 결측이면 추세 판단 불가로 응답한다. 끝점 변화는 매 기간 단조 증가·계절조정 추세·예측을 뜻하지 않는다. 원인 추측·운항 추천은 하지 않는다.

수치·순위·차이·비율은 결정적 계산 도구 결과만 인용한다. 모델이 직접 계산하거나 없는 셀을 만들지 않는다. 답에는 국가·원천 표·운송모드·분류판/레벨·분류·방향·기준/비교 기간·단위·계산 분모·조회 시각·잠정/누락/공표 지연·관련 화면 링크와 사용 셀/계산 근거를 포함한다. 확인 가능한 근거가 없으면 답변 불가와 필요한 조건을 제시한다.

무료 또는 로컬 모델은 아직 선정·실행 검증하지 않았다. 후보의 이용 조건·한국어 질의 변환·근거 준수·장비 성능을 구현 전에 확인해야 한다. 유료 키나 외부 전송은 임의 허용하지 않는다. 모델 오류·가용성 부족 시 정형 조회와 근거 표로 대체하되 이것만 동작하면 “AI 완료”로 처리하지 않는다. 모델 장애는 AIS 수집기 재시작의 근거가 아니다.

## 10. 에이전트 협업 흐름

정상 흐름은 **관찰 → 사건 생성 → 진단 → 허용 조치 → 독립 검증 → 종료 기록**이다. 관측 공백·위치 이상은 표시·이력 흐름으로 분기한다. 원인 불명이나 근거 부족은 자동 변경 없이 사람에게 인계한다.

| 상태 | 진입 조건·다음 동작 | 종료/다음 상태 |
|---|---|---|
| 감시 중 | 정상 조회·생존 확인·관측별 판정 | 오류 증거가 있으면 탐지 |
| 탐지·진단 | 같은 수집원의 열린 사건에 증거 합침; 최초 Diagnosis 호출을 활성 시작으로 기록 | 알려진 복구 대상→조치, 자료 사건→표시, 불명→인계 |
| 조치 | 잔여 한도·기한 확인 후 Recovery 호출 | 완료 보고→독립 검증, 실패→남은 정책 또는 차단 |
| 독립 검증 | 신규 유효 자료·원천 의미·생존·보존 상태 확인 | 성공→정상 종료, 실패/판단 불가→남은 한도 또는 차단 |
| 회로 차단 | 정규 수집 요청·변경 조치 중지, 마지막 자료·실패 근거 표시 | 300초 뒤 단 한 번 30초 이내 읽기 확인 |
| 회복 관측/인계 대기 | 냉각 후 확인 성공도 회로는 유지; 실패·불가도 유지 | 운영자 확인·재개 요청 대기 |
| 운영자 재개 확인 | 원인·수동 조치 확인 후 30초 한도 독립 읽기 검증 | 성공→사건 종료·차단 해제, 실패/불가→같은 사건 중단 유지 |

닫히지 않은 사건의 시도 한도는 정규 스케줄·브라우저 새로고침·수집기 재시작·냉각·운영자 버튼으로 초기화하지 않는다. 정상 종료 후 새 장애 증거가 생긴 경우에만 새 사건과 한도를 부여한다.

활성 구간은 최초 Diagnosis 호출부터 180초 이내다. 냉각 후 읽기 확인과 운영자 대기는 차단 이후의 별도 인계 구간이다. 이 시간을 숨겨 활성 복구 성공처럼 집계하지 않는다. 대기 중 외부 상태가 저절로 회복돼도 운영자 확인 전 정규 수집은 재개하지 않는다.

### 공통 상한과 독립 성공 조건

| POL-09 통계 검증 | 같은 원천·보고국/상대국·운송모드·분류판·주기·방향·단위·기존 공개 기간을 독립 확인. 새 월/분기/연 공표를 요구하지 않음 |

일반 추가 요청과 독립 검증 요청은 로그에서 구분한다. 검증은 새 정상 후보를 얻은 조치 뒤에 수행하며 실패 시 다시 조치하려면 남은 추가 요청 한도와 180초 기한을 충족해야 한다. 성공 근거가 없다고 검증 자체를 무한 반복하지 않는다. 냉각 후 확인은 1회이며 운영자 재개 검증은 명시적 요청당 1회다.

|---|---|---|---|---|---|---|---|---|
| F-01 5xx | 원천 응답 5xx | 코드·시각·원천 상태 | 정해진 대기 후 재조회 | 남은 한도 내 재조회, 이후 차단 | 추가 요청 3회 | 차단 후 재개 시 필요 | 마지막 정상 저장본 보존 | AIS/통계별 독립 조건 |
| F-02 타임아웃 | 10초 응답 미완료 | 요청·대기 이력 | 대기 종료 후 재연결/재조회 | 남은 한도 내 재시도, 이후 차단 | 추가 요청 3회 | 차단 후 재개 시 필요 | 늦은 중복 응답이 현재 자료를 덮지 않음 | AIS/통계별 독립 조건 |

롤백은 이전 정상 데이터·상태를 보존하는 수준이다. 외부 시스템이나 관측 원본을 되돌려 쓰지 않는다. 전체 PC가 꺼진 상태, 감시 주체까지 중단된 상태, 외부 제공자의 장애를 이 앱이 자동 복구한다고 약속하지 않는다.

## 12. 자율성과 Human-in-the-loop

| 구분 | 행동·조건 |
|---|---|
| 자동 실행 가능 | 알려진 요청 실패의 제한 재조회/재연결, 증거가 있는 허용 수집기 중단의 1회 재시작, 독립 검증, 마지막 정상 자료 유지, 규정된 앱 보존기간 정리 |
| 사람 확인 필요 | 회로 차단 후 원인·수동 조치 확인 및 재개 요청, 임계값·허용목록·복구 정책의 변경 결정 |
| 자동 실행 금지 | 임의 쉘 명령·외부 서버/선박 조작·허용목록 밖 재시작·원본 좌표 변조·운영 데이터 삭제·인증정보 변경·비용 확대·자동 승인 |

운영자 확인은 같은 사건의 시도 예산을 추가하는 버튼이 아니다. 확인 이후 읽기 검증에 실패하면 중단 상태를 유지한다. 정책 변경이나 외부 조치는 이 MVP의 자동 실행 기능이 아니며, 승인 기록 없이 적용된 것으로 처리하지 않는다.

화면에 사건 상태·원인 후보·불확실성·시도 횟수·기한·검증 결과·필요한 사람 판단을 남긴다. 전달 실패와 사용자의 미확인을 구분한다. 운영자는 실습 팀 담당자 1명이며 실명 지정은 후속 실습 준비 사항이다.

## 13. 기능 요구사항

활성 기능은 FR-001~003·005~019의18개다. FR-004는 §20의 퇴역 이력에만 보존한다. 아래 초기 정책 ID는 워크시트의 같은 ID와 동일한 의미다. 숫자는 실습용 설계 가정이며 검증된 항해 기준·정확도·확률이 아니다.

### 관측·표시 정책

| 정책 ID | 초기 기준 | 이유·예외 |
|---|---|---|
| GAP-01 | 마지막 신규 원본 관측 시각 기준 10분 이하 최신, 10분 초과~15분 미만 지연, 15분 이상 미수신 | 5분 조회 때 상태를 판단하므로 전환이 최대 한 조회 주기 늦을 수 있음 |
| GAP-02 | 마지막 신규 원본 시각과 마지막 유효 위치 시각을 분리. 중복 관측은 두 시각을 갱신하지 않음 | 원본이 계속 오지만 좌표가 이상하면 위치 이상으로 표시하며 미수신·수집 장애로 바꾸지 않음 |
| POS-01 | 선박 식별자·전체 관측 시각·좌표 필요. 위도 -90~90, 경도 -180~180. 같은 시각 다른 위치는 충돌, 과거 관측은 현재 위치를 덮어쓰지 않음 | 원천의 미제공 표식은 결측 처리. SOG/COG 누락만으로 위치를 폐기하지 않음 |
| POS-02 | 직전 유효 위치와 0초 초과~30분 이하 간격에서 거리 0.5해리 초과이면서 계산 이동속도 60노트 초과면 도약 의심 | 30분 초과 공백은 도약 판정 유보·항적 단절 표시. 60노트는 실제 최대속도가 아니라 검토용 초기 기준 |
| POS-03 | 도약 이후 1~10분 간격의 서로 다른 시각 신규 후보 2개가 서로 POS-02 조건에 해당하지 않으면 두 번째부터 추적 재개 | 이전 위치와 선을 잇지 않고 사건 보존. 동일 선박의 실체·정확성 확정이 아님 |
| POS-04 | 미래 시각 허용 오차는 초기안에서 0초. 원천 전체 시각을 UTC로 해석한 뒤 현재 기준 시각보다 미래이면 시간 이상으로 보류. 초/밀리초 단위 오류·전체 시각 부재도 동일 처리 | 잘못된 시각은 최신성·공백 종료·평균·항적·복구 성공 근거에서 제외. 원본만 보존하며 마지막 신뢰 가능한 관측 시각을 갱신하지 않음. 실습은 동일 UTC 시계, 재생은 논리 시계 사용; 시계 불일치가 잦으면 정책 재검토 |
| AVG-01 | 최근 30분 유효 SOG의 산술평균, 노트. 최신 표본에서 거슬러 가며 공백 10분 초과 이전 표본 제외. 서로 다른 시각 3개 이상, 표본 구간 10분 이상, 최신 표본 나이 10분 이하 필요 | 최근 관측 속도 평균이라는 이름과 실제 집계 구간·표본 수를 함께 표시 |
| AVG-02 | 중복·충돌·도약 의심·미제공 SOG 제외, 유효 0노트는 포함. 부족하면 데이터 부족과 사유 표시 | 항해 전체 평균·시간 가중 평균으로 설명하지 않으며 공백을 0이나 추정 속도로 채우지 않음 |

기본 시각은 공급자별 계약의 **전체 관측 시각**이다. 다음 Digitraffic 단위·미제공 값은 해당 원천에만 적용하며 추가 원천 계약은 OPEN-11에서 확인한다. Digitraffic REST 위치 자료의 timestampExternal은 밀리초 단위 전체 시각으로 해석하며, timestamp의 분 내 초 값으로 대체하지 않는다. MQTT 등을 후속 선택하면 그 원천의 초 단위 전체 시각을 별도 변환해야 한다. 수집 시각·메타데이터 갱신 시각은 위치 관측 시각과 다르다. SOG 102.3, COG 360 등 원천의 미제공 값은 결측 처리한다. ### FR-001 선박 감시 대상과 수집

- 설명: 국가·100척 제품 상한 없이 활성 공급자의 실제 확보 집합을 동적 감시한다. REQ-01·15.
- 입력: 공급자/스트림/설정 범위·자격/쿼터/프로토콜 계약, 유효 관측·식별자·원천 시각, 영속 집합.
- 기대 동작: S-01/POL-01 신규 추가·집합 버전/변경 이력과 REST5분/스트림 수신을 적용한다. 원본·중복·충돌·대표 전체 레코드를 구별한다.
- 예외 상황: 0척·커버리지/자격 부족은 실제 확보량과 사유를 표시한다. 필터·미수신으로 선박/항적/열린 사건을 삭제하지 않고 쿼터 우회·유료 전환을 금지한다.
- 인수조건: 100척 하드캡이 없고 전체 일치 수와 표시 수를 구별한다. 재기동에도 집합/사건/한도가 보존되며 중복으로 최신성·평균·횟수를 늘리거나 출처가 다른 위치/SOG/COG를 합성하지 않는다.

### FR-002 신호 공백과 재관측

- 설명: 선박별 공백을 수집원 장애와 구분한다. REQ-03·10.
- 입력: 신뢰 가능한 마지막 신규 원본 시각·마지막 유효 위치·현재 시각.
- 기대 동작: GAP-01~02 기준으로 최신/지연/미수신과 경과 시간을 표시한다. 미수신은 회색으로 나타낸다.
- 예외 상황: 신규 원본은 있으나 위치가 이상하면 위치 이상으로 표시한다. 시간이 잘못된 원본은 공백 종료 근거가 아니다.
- 인수조건: 10분·15분 경계에서 지정 상태가 다음 조회에 반영되고, 유효 재관측 후 표시가 복귀하며 공백 이력이 유지된다.

### FR-003 위치 유효성과 도약 의심

- 설명: 이상 좌표가 유효 항적·평균 기준을 오염시키지 않게 한다. REQ-02.
- 입력: 식별자·전체 시각·연속 좌표.
- 기대 동작: POS-01~04를 적용하고 원본과 판정을 분리한다. 도약 후보 이후 두 연속 후보 조건으로 추적을 재개한다.
- 예외 상황: 시간 차 30분 초과는 도약 판단 유보, 같은 시각 다른 좌표는 충돌, 잘못된 시간은 시간 이상이다.
- 인수조건: 0.5해리와 60노트 조건을 모두 초과한 지정 관측만 도약 의심으로 분류하며 재개 시 이전 항적과 선을 잇지 않는다. 의심 원본은 보존된다.



### FR-005 선박 상세 카드와 평균 속도

- 설명: 근거가 있는 선박 정보·항만 시각을 클릭 카드로 제공한다. REQ-05·10.
- 입력: 관측·선박 메타데이터·항만 방문/항해 연결·품질 이력·최근 유효 SOG·사진 권리 근거.
- 기대 동작: S-02의 이름/MMSI/IMO·기국·원천 선종·신선도·SOG/COG·평균·흘수·목적지·항만/시각·상태를 항목별 출처/원천 갱신/수집 시각과 표시한다. 항적 보기로 연결한다.
- 예외 상황: 항목별 부족 사유를 표시하고 AIS ETA의 연도를 만들지 않는다. 정확한 항해 연결 없이 출발→도착을 구성하지 않는다. 허가 사진이 없으면 자리표시자다.
- 인수조건: ATD/ATA/ETA/ETD의 실제/예상·입항/출항·연결 방문을 구별한다. 원천 없는 화물·국가·상세 선종을 만들지 않는다. 평균은 AVG-01~02의 30분/3표본/10분 조건에서만 제공한다.

### FR-006 기국 필터

- 설명: 등록국이 확인된 감시 선박을 골라 본다. REQ-06.
- 입력: 동적 감시 집합·확인된 등록국·기국 미확인 상태.
- 기대 동작: 전체/확인된 기국/미확인으로 목록과 지도를 함께 필터링한다.
- 예외 상황: 기국이 없으면 별도 미확인 항목에 남기며 현재 해역으로 대체하지 않는다.
- 인수조건: 필터 결과가 감시 집합의 부분집합이고 지도·목록의 수가 일치한다. 통계 분석 대상 국가 사이드 선택과 혼동되지 않는다.

### FR-007 해상 화물 원천과 자료 모드

- 설명: 국가별 해상 상품·핀란드 월 품목·Eurostat 분기 형태의 세 모드를 분리한다. REQ-07·09·18.
- 입력: 실제 Sea 원천 셀/HS판·레벨·중량·보고국/상대국·방향·기간, 12jd 월·Country=Total·톤, mar_go_qmc 분기·방향·형태·THS_T.
- 기대 동작: S-03 계약과 월24+1/분기8+1/연2+1 초기안, 하루1회 공표 확인·원값/원단위/수정 이력 보존을 적용한다.
- 예외 상황: 미확인·미지원·미발표·기간 없음·비공개 결측·조회 실패를 구별한다. HTTP200/요청 motCode만으로 Sea 성공을 주장하지 않고 WATER/All Modes/미지정으로 대체하지 않는다.
- 인수조건: 실제 응답 Sea·상품 레벨·단위·이용 조건이 확인된 조합만 지원한다. IN/OUT 하역/적재를 수출입 상품으로 바꾸거나 AIS선종/국가 통계로 선박 적재를 생성하지 않는다. 미지원 반환과 실제 해외 Sea 확보를 구별한다.

### FR-008 두 단계 품목 분류

- 설명: 해상 상품 HS2→HS4, 핀란드 월 서비스6→공식16, 분기5화물형태를 분리한다. REQ-08·18.
- 입력: 원천 분류체계·개정판·코드·레벨·부모·명칭과 원천별 매핑.
- 기대 동작: 확인된 상품 한 단계 펼침과 중복 없는 합산을 제공하고 원천 판/레벨/코드를 보존한다. 아래 매핑은 핀란드 월 모드에만 적용한다.
- 예외 상황: 미확인 코드·판 변경·필수 하위 누락/비공개는 불완전으로 표시한다. HS·12jd·Eurostat 임의 매핑이나 일반화물→생활용품 재분류는 금지한다.
- 인수조건: HS6 드릴다운·다른 판 자동 비교·상위/하위/전체 중복 합산이 없다. 핀란드 16품목은 아래 상위에 한 번씩만 포함한다.

| 서비스 상위 분류 | 공식 하위 품목군의 한국어 표시 |
|---|---|
| 목재·제지 | 원목, 제재목, 펄프, 종이, 합판·단판 |
| 연료 | 원유, 석유제품, 석탄·코크스 |
| 금속·광물 | 광석·정광, 금속·금속제품, 원료광물·시멘트 |
| 화학·비료 | 화학제품, 비료 |
| 곡물 | 곡물 |
| 일반·기타 화물 | 일반화물, 기타 상품 |

상위 6분류는 서비스 편의를 위한 묶음이며 공식 분류 계층이라고 주장하지 않는다. 생활용품·세제·식기는 12jd의 세부 분류가 아니다. 별도 HS 모드는 실제 확인된 상품만 다룬다. 공식 코드·명칭을 보존하고 번역 명칭과 구별한다. [12jd 선택 표](https://statfin.stat.fi/PxWeb/pxweb/en/StatFin/StatFin__uvliik/12jd.px/)

### FR-009 물량·비중·직전 기간 변화와 그래프

- 설명: 같은 원천·정의·국가·주기·방향·분류 범위의 변화를 계산한다. REQ-09·10·18.
- 입력: 같은 보고국/상대국·원천·운송모드·분류판·기간·방향·단위의 Q·원천 전체값 T와 달력상 직전 월/분기/연도 Qprev·Tprev, 단위/누락 상태. 페이지 품목 합계는 전체 분모가 아니다.
- 기대 동작: 비중=100×Q/T, 직전 기간 차이=Q−Qprev 톤, 증감률=100×(Q−Qprev)/Qprev. 비중 변화는 100×Q/T−100×Qprev/Tprev 퍼센트포인트(%p)로 별도 표시한다. 월/분기/연 모드별 라인 그래프와 근거 표·분모를 제공한다.
- 예외 상황: T=0이면 비중 불가, Qprev=0이면 증감률 불가지만 두 값이 있으면 차이는 가능하다. 필요한 값 누락·비공개면 계산/합산 불가 또는 불완전으로 표시하며 0으로 채우지 않는다. TOTAL=IN+OUT을 가정하지 않는다.
- 인수조건: 같은 기간·원천 정의·방향·분류·단위로만 비교하고 비율은 계산 후 소수점 1자리 반올림한다. 월24개/분기8개/연2개 달력 기간과 직전 비교1기간을 구별한다. 결측을 건너뛰거나 다른 분류판을 자동 비교하지 않는다. 누락 구간을 보간하지 않고 국가 간 비교는 공통 기간만 쓴다.

### FR-010 수집 장애 탐지·진단

- 설명: F-01~03을 관측 품질 사건과 구별한다. REQ-11.
- 입력: 요청 결과·응답 시간·생존 상태·관측 신선도.
- 기대 동작: 요청별 5xx/10초 초과, 생존 3회 연속 실패를 사건으로 기록하고 Diagnosis가 증거와 원인 후보를 반환한다.
- 예외 상황: 단독 신호로 외부 제공자 전체 장애를 확정하지 않는다. 통계 미발표·개별 선박 공백·커버리지 부재·공급자 제외 선박은 수집 오류가 아니다. 인증/권한/쿼터는 대기·중단·인계하며 무조건 재시작하지 않는다.
- 인수조건: 세 모의 장애가 구분되며 감시가 계속 작동한다. 동일 수집원의 열린 사건에 반복 증거가 합쳐진다.

### FR-011 제한된 복구 실행

- 설명: 허용 범위 안의 조치만 실행한다. REQ-11·13.
- 입력: 진단·정책·잔여 한도·허용 대상.
- 기대 동작: 추가 요청 3회/5·15·30초 대기·허용 수집기 재시작 1회·활성 180초를 적용한다.
- 예외 상황: 요청 제한·불명 원인·남은 기한 부족은 안전 중단한다. 재시작 실패를 반복 재시작으로 해결하지 않는다.
- 인수조건: 모든 조치에 사건·시도 ID와 전후 결과가 있고 횟수·시간 상한 밖의 조치가 0건이다.

### FR-012 회로 차단·인계·재개

- 설명: 실패가 자동 루프로 이어지지 않게 한다. REQ-13.
- 입력: 실패·상한·기한, 냉각 시각, 운영자 확인.
- 기대 동작: §10의 상태 전이와 POL-07·11을 적용한다. 300초 뒤 읽기 1회 이후에도 운영자 확인과 새 검증 전에는 차단을 유지한다.
- 예외 상황: 확인 실패·운영자 미확인·프로그램 재시작은 같은 사건·한도·중단 상태를 유지한다.
- 인수조건: 냉각 검증 성공만으로 정규 수집이 재개되지 않는다. 운영자 요청 후 독립 검증에 성공한 경우에만 사건을 닫는다.

### FR-013 복구 결과 독립 검증

- 설명: 실제 데이터 정상화 근거가 있는 사건만 성공으로 종료한다. REQ-12.
- 입력: 사건 전 관측 기준·새 원천 자료·생존·저장/표시 상태.
- 기대 동작: POL-08·09로 자료 유형을 구별해 최대 30초 내 성공/실패/판단 불가를 반환한다.
- 예외 상황: HTTP 성공·재시작 응답·캐시·미래 시각만 있으면 성공 불가.
- 인수조건: AIS는 같은 공급자/스트림/범위의 사건 기준 이후 새 유효 관측1건 이상·나이0~10분을 확인한다. B관측으로 A를 종료하지 않고 개별 미수신은 남긴다. 통계는 POL-09의 같은 계약/기존 공개 기간으로 검증한다.

### FR-014 누적 이력과 출처

- 설명: 관측 2년과 운영 종료 로그 30일을 구별해 근거를 보존한다. REQ-10·14·16.
- 입력: 원본·판정·정책 버전·항적 단절·사건/시도/검증·통계 이력, observed_at/first_received_at/closed_at.
- 기대 동작: §15의 UTC 달력 2년 경계 포함·오류 시각 격리·조회 즉시 경계·하루 1회 물리 정리를 적용한다. 종료 로그는 closed_at+30일, 열린 사건 필수 근거는 종료 전 유지한다.
- 예외 상황: 시각 오류 원본의 최초 수집 시각을 재조회로 연장하지 않는다. 열린 사건 때문에 2년 초과 보존된 근거를 일반 항적 범위로 확대하지 않는다. 저장 실패는 정상 완료로 처리하지 않는다.
- 인수조건: 윤일·경계·중복·오류 시각·종료/열린 사건 정책을 구별하며, 사건 상세 만료 후에도 2년 항적의 최소 단절 근거가 남고 깨진 링크가 없다. 원본은 불변이고 실제 확보 기간을 표시한다.

### FR-015 운영자 사건 확인

- 설명: 사람에게 필요한 판단을 전달한다. REQ-13·14.
- 입력: 차단/불명/검증 결과, 담당자의 확인.
- 기대 동작: 로컬 운영 경로에 사건·근거·시도·필요 조치·전달/확인 상태를 지속 표시하고 재개 요청을 기록한다.
- 예외 상황: 전달 실패는 미전달로 남기며 일반 조회 화면에서는 재개할 수 없다.
- 인수조건: 운영자 확인과 독립 검증이 별도 기록이며 임의 명령·자동 승인·외부 메시지 기능이 없다.

### FR-016 공통 화면 상태와 접근

- 설명: 자료의 부족·지연·오류·복구·조회 AI 실패를 사용자가 구별한다. REQ-05·09·10·15·17~19.
- 입력: 자료 상태·사용자 선택·오류·모드.
- 기대 동작: §7의 로딩·빈 상태·부분 부족·지도 실패·재생·국가 전환·AI 대체 모드를 표시한다. 키보드로 카드·항적 기간·국가 선택·분류·수치 표·질문을 이용하고 색+선형+범례+문구를 제공한다.
- 예외 상황: 지도나 외부 요청이 실패해도 보유한 목록·시각·상태를 유지한다.
- 인수조건: 색 없이 상태를 읽을 수 있고 팝업 종료 후 초점이 복원된다. 실시간/재생, 관측/계산/품질 판정, 통계 기준기간을 혼동시키는 표기가 없다.

### FR-017 기간별 항적과 공백 표현

- 설명: 실제 축적 범위에서 기간별 관측·공백·이상 이력을 조회한다. REQ-16·17.
- 입력: 감시 선박·기간·관측 원본/품질 판정·공백/단절 구간·정책 버전.
- 기대 동작: S-05의 기본 24시간·7일·30일·1년·2년·사용자 기간, 실확보 범위와 구간 표를 제공한다. 순수 미관측 구간은 재수신 후 양 유효점 사이 주황 점선으로 표현한다.
- 예외 상황: 열린 공백에 종점을 만들지 않는다. 도약/충돌/시각 오류는 붉은 단절이며 POS-03 재개 전후를 연결하지 않는다. 15분 공백 표시와 30분 도약 판정 유보는 별개다.
- 인수조건: 연결선을 실제 경로로 설명하지 않는다. 축약은 응답/렌더링에 한정하고 원본·각 구간 양끝점·공백/이상 경계를 보존한다. 원본/표시 수·축약·페이지/기간 축소 안내가 있다.

### FR-018 국가 사이드 선택과 가용성

- 설명: 국가 상한 없이 실제 확인된 통계 조합만 지원한다. REQ-07·18.
- 입력: 국가·원천·운송모드·분류판/레벨·주기·방향·분류·기간과 조합별 가용성/조회 상태.
- 기대 동작: S-03 원천 코드·세 자료 모드와 상태를 표시한다. 국가 변경 시 호환 선택을 유지하고 불가 선택은 가용 기본값과 변경 이유를 알린다.
- 예외 상황: 이전 국가 요청의 늦은 응답을 새 국가 값으로 표시하지 않는다. 가용 기본값도 없으면 선택 해제·자료 부족을 표시한다. 최신 공개 기간 차이를 숨기지 않는다.
- 인수조건: 미확인과 미지원/미발표/기간 자료 없음/비공개 결측/일시 실패가 서로 다르고 0으로 대체되지 않는다. 공통 기준 없는 국가 비교를 차단한다. 통계 국가 전환이 AIS 감시 집합·기국을 바꾸지 않는다.

### FR-019 서비스 보유 데이터 조회 AI

- 설명: 자연어를 제한 조회 조건으로 해석하고 보유 자료·결정적 계산에 근거해 답한다. REQ-19.
- 입력: 사용자 질문·명시한 화면 선택·조합 가용성·허용 읽기 결과·계산 근거.
- 기대 동작: §9의 조회 AI 7항목 및 S-06을 따른다. 적용 조건을 첫 줄에 밝히고 답에 원천/국가/상대국/운송모드/분류판/레벨/주기/분류/방향/기간/단위/분모/조회 시각/지연·잠정·누락/화면 링크를 포함한다.
- 예외 상황: 방향·모드 모호성은 명확화하고 3기간 미만·중간 결측의 추세는 판단 불가다. 모델 실패는 정형 조회+근거 표, 자료 없으면 답변 불가. 외부 검색·임의 SQL/쉘/파일/URL·복구 조작과 지시 주입을 허용하지 않는다.
- 인수조건: 실제 모델의 제한 조건 해석·읽기 도구 연계와 근거 응답이 확인돼야 AI 완료다. 모델의 수치 직접 계산·없는 셀 생성·근거 없는 원인/예측/운항 추천이 없고 원천 문자열로 권한이 바뀌지 않는다. 대체 화면만 구현한 것은 AI 완료가 아니다.

운영 복구 사건·시도·독립 검증 로그는 사건 종료 후 30일 보존한다. 열린 사건의 필수 근거는 종료 전 삭제하지 않아 일부 원본이 2년을 넘을 수 있지만 이는 일반 항적 조회 범위를 늘리지 않는다. 종료 후 각 기록의 기한을 적용한다. 사건 상세가 먼저 만료돼도 2년 항적에 필요한 단절 시간·유형·정책·최소 근거는 별도로 남기고 “운영 사건 상세 보존 만료”로 표시하며 삭제된 상세의 깨진 링크를 제공하지 않는다. 월 통계는 표시 24개월+직전 비교 1개월, 분기 통계는 표시8분기+직전 비교1분기, 연자료만 있으면 연2년+직전 비교1년 초기안으로 명시하며 비교 자료가 없으면 비교 불가다. 보유 통계의 원천·수정 버전과 누락 상태도 함께 보존한다. 대화 원문은 기본적으로 세션 안에서만 보관하고 2년 관측 정책을 적용하지 않는다.

2년 보존은 수집 시작 전 과거 2년의 즉시 확보를 약속하지 않는다. 공개 AIS 최신값과 서비스의 실제 축적 범위를 구분하고 시작·종료 시각과 미확보 기간을 표시한다. 과거 고정 100척 범위의 100×288×730=21,024,000건은 역사적 단순 예시일 뿐 현재 규모 계획이나 저장 상한이 아니다. 현재 추정은 공급자별 실제 신규 관측률×보존 기간에 원본·판정·색인·출처 비용을 더하며 스트림 원본과 5분 스냅샷을 구별한다. 730/731일의 달력 차이도 반영한다. 페이지·영역·큐·저장·과부하·취소의 수치와 장기 성능 예산은 OPEN-09 및 작업 1.4의 미확인 게이트다. 과부하를 이유로 조용히 100척만 저장하거나 2년 보존을 줄이지 않는다.

시각은 UTC로 기록하고 화면 기본 표시는 Asia/Seoul로 한다. 통계 기준월은 원자료의 월 정의를 유지한다. 원천 관측·수집·공표·수정 시각을 혼합하지 않는다. 모의/재생 자료에는 별도 모드와 논리 시계를 붙이며 실시간 이력에 합산하지 않는다. 비밀키·토큰·비밀번호와 불필요한 개인정보는 로그에서 제외한다.

### 시간과 성과의 정의

- 발생 시각: 알려진 모의 장애의 시작. 실제 외부 장애 시작을 모르면 미확인.
- 탐지 시각: Monitor가 사건을 생성한 시각.
- 활성 시작: Orchestrator가 해당 사건의 Diagnosis를 처음 호출한 시각.
- 첫 조치 시각: Recovery가 실제 첫 허용 행동을 시작한 시각.
- 정상 확인 시각: Verification이 유효 자료와 정상 기능을 독립 확인한 시각.
- 탐지 소요시간 = 탐지−발생; 여러 사건 평균은 MTTD.
- 전체 정상화 소요시간 = 정상 확인−발생; 알려진 발생 시각을 가진 정상화 사건의 평균은 MTTR.
- 활성 복구 시간 = 정상 확인−활성 시작. **180초 목표는 이 값**이며 발생부터 180초라는 뜻이 아니다.
- 차단 이후 냉각·읽기 확인·운영자 대기는 인계 구간으로 별도 기록. 사람 확인 후 정상화는 자동복구 성공에서 제외하고 전체 경과시간을 함께 보고한다.
- 자동복구 성공률은 사전에 정의한 복구 가능 9회 중 기한 안에 독립 정상화한 횟수/9다. 실패·미완료를 분모에서 빼거나 안전 중단을 성공으로 넣지 않는다.

REST 5분 정규 조회 직후 생긴 요청 장애는 다음 조회까지 탐지가 늦어질 수 있다. 따라서 실제 발생부터의 MTTR은 활성 예산보다 길 수 있다. 발생 시각 미확인·재생 논리 시계·실시간 시계의 결과는 분리한다.

PRD 문서 완료 조건은 필수 20절·요구사항·근거·상태가 갖춰지고 독립 검수가 통과한 뒤 사용자가 최종 승인하는 것이다. 제품 완료는 별도로 위 인수조건의 실제 결과가 확인돼야 한다. 문서 검수 통과를 제품 동작 검증으로 대체하지 않는다.

## 19. 미결정 사항

요구 범위는 사용자 선택과 위임 초기안으로 정리했다. 모델 선정·실행 및 장기 성능은 구현 준비 판단을 막을 수 있는 미확인 사항이며, 문서 승인과 기술 준비 완료를 구별한다. 다음 게이트는 문서 작성의 차단 사유가 아니지만 확인 전 해당 연동 지원·구현 준비 완료를 선언할 수 없다. 작업목록의 선행 작업과 연결해 확인하거나 정의된 미확인/자료 부족 상태로 남긴다.

다음은 당시 재검수 제출 기록이다: PRD v0.2.1과 워크시트 v0.5.1을 REV-01~22 전체 재검수 대기로 제출했다. 이후 승인 원본의 통과 결과는 위 기록에 별도로 연결했다. 최초 제출 v0.2/v0.5의 독립 검수에서 REV-08은 분기 기간을 화물형태 개수로 잘못 쓴 표현 때문에 실패했고 나머지 21개 규칙은 통과했다. 해당 판정은 최초 제출본의 역사이며 현재 수정본에 재사용하지 않는다. 이번 수정은 기간을 최근 공개 8분기(+직전 비교 1분기 확보 목표), 분류를 가용 5개 화물형태 및 TOTAL로 구별하고 NFR 표 연결·협업 표 열 구분을 보완했다.

과거 R01~R25 및 25개 PASS 기록도 PRD v0.1/워크시트 v0.4에만 유효하다. 수정 전 원문·SHA-256은 before_prd / before_worksheet, 최초 제출 원문·SHA-256·배정표는 after_prd / after_worksheet에 유지한다. 이번 수정 제출본은 새 키 after_prd_r2 / after_worksheet_r2에 원문·SHA-256·REV 배정표를 보존하며 기존 키는 덮어쓰지 않는다. 독립 검수 응답의 규칙별 판정·근거·대상 해시는 조정 담당이 해당 묶음에 연결한다. 통과 기록만 추가하려고 검수 대상 문서를 다시 고치지 않는다.

최초 검수 실패 시 최초 제출 원문을 기준으로 필요한 부분만 수정한다. 후속 단계 실패 시 직전 유효 통과 체크포인트에서 수정하고 영향을 받는 가장 이른 단계부터 순차 재검수한다. 통과한 단계의 원문·해시·규칙 배정·판정/근거는 덮어쓰지 않고 복구 가능하게 보존한다. 새 버전에 옛 판정을 재사용하지 않는다. 검수 실행이 불가능하면 통과를 꾸미지 않고 제한을 보고한다.
